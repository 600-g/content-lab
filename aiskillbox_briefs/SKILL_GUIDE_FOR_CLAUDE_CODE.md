## 🚨 절대 금지 (이거 어기면 데이터 소실됨)

1. **replace_content 사용 전 반드시 fetch로 기존 내용 확인**
   - fetch 결과를 사용자에게 보여주고 승인 받은 후에만 replace 실행
   - 승인 없이 replace_content 실행 금지

2. **코드/프롬프트 원문 축소 금지**
   - 코드블록 안의 내용은 한 글자도 요약하지 말 것
   - `[[CODE_BLOCK_N]]` 같은 placeholder로 치환 금지
   - 긴 프롬프트(100줄 이상)도 전문 그대로 유지

3. **제목 첫 글자 자르기 금지**
   - "AI" → "I", "Anthropic" → "nthropic" 버그 주의
   - 스킬명 속성 업데이트 후 반드시 fetch로 검증

4. **"두근컴퍼니 적용" 2줄 요약으로 본문 교체 금지**
   - 이게 이전에 데이터를 전부 날린 원인임

## 📐 페이지 본문 구조 (이 순서 고정)

```
1. callout (💡 아이콘, blue_bg)
   → 이 스킬이 뭔지 1~2문장. 핵심 키워드 **굵게**

2. ## 이게 뭔가요?
   → 배경 + 어떤 AI에서 쓰는지 + 무료/유료 표시
   → 💰 유료 필요: OO / ✅ 무료 대안: OO

3. ## 따라하기
   → 번호 매긴 단계별 가이드
   → 코드/프롬프트는 코드블록(```)으로
   → 프롬프트 팩이면 ### 소제목으로 각각 구분

4. ## 활용 예시
   → 구체적 시나리오 1~3개
   → 두근 프로젝트(두근펫, 매매봇, 첼시인스타 등) 대입 예시

5. ## 💡 아이디어
   → 수익화 가능성, 프로젝트 강화 방안
   → 내용 없으면 이 섹션 자체 삭제

6. ## 주의사항
   → 흔한 실수, 비용 주의
   → 내용 없으면 이 섹션 자체 삭제

7. ## 출처
   → [원본 제목](URL) + 저자 정보
```

## ⚠️ 허용되지 않는 대제목

아래 대제목은 사용 금지. 위 7개만 허용:
- ❌ "어떻게 작동하나요?"
- ❌ "이렇게 쓰면 효과적이다"
- ❌ "두근컴퍼니 적용"
- ❌ "언제 쓰나"
- ❌ "원리"
- ❌ "단계"
- ❌ "따라 하기 (단계별)"  ← "따라하기"로 통일

## 서식 규칙

- callout: 💡 아이콘, blue_bg, 핵심만 굵게
- 코드블록: 프롬프트/명령어/JSON/코드 전부. 인라인 코드로 넣지 말 것
- 굵은글씨: 단계명, 도구명, 핵심 키워드에만. 문장 전체를 굵게 X
- 번호 목록: "따라하기" 단계에서만. 나머지는 - (글머리 기호)
- 이모지: callout 💡만. 본문에 이모지 남발 금지 (💰✅는 비용 표시에만)
- 빈 섹션: 억지로 채우지 말고 섹션 자체 삭제

## 작업 흐름 (1페이지당)

```
1. notion-fetch로 현재 페이지 내용 확인
2. 출처 URL에서 원본 읽기 (web_fetch 또는 notion-fetch)
3. 원본에서 핵심 내용 추출 (코드/프롬프트 전문 포함)
4. 위 템플릿 구조에 맞게 본문 작성
5. replace_content로 적용
6. 적용 후 notion-fetch로 검증
   → 검증 체크리스트:
   - [ ] callout 있는가?
   - [ ] 대제목이 7개 중에만 있는가?
   - [ ] 코드블록이 깨지지 않았는가?
   - [ ] 제목 첫 글자 안 잘렸는가?
   - [ ] 프롬프트/코드가 요약되지 않고 전문 유지되었는가?
```

## 🔑 핵심 원칙

- **간소화가 아닌 최적화**: 길어도 필요하면 유지. 가독성 강화가 목적
- **나무위키 스타일**: 처음 보는 사람도 따라할 수 있게
- **원문 가치 보존**: 프롬프트 전문, 코드 전문이 이 DB의 핵심 자산
