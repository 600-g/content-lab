💡 이 스킬은 **Claude Code 토큰 73% 절약 통합 패턴**으로, `/usage` `/compact` `/clear` 명령 + CLAUDE.md 룰북 + 서브에이전트 위임 + autocompact 조정 + Skill 분할의 5축 전략입니다.

## 이게 뭔가요?

**Claude Code 사용 시 토큰 소비를 73% 까지 줄여 작업량을 3배 이상 늘리는 통합 절약 가이드**. 원본 콘텐츠가 본문 없이 단톡방 안내만 포함되어 있어, 광범위한 토큰 절약 베스트 프랙티스를 종합 정리.

**왜 토큰을 아껴야 하나**:
- Claude Code Pro / Max 모두 **주간 한도** 가 있음 (Pro 는 더 빠르게 도달)
- 같은 한도 안에서 더 많은 작업 처리 = **체감 작업량 3배**
- 같은 작업도 토큰을 적게 쓰면 **응답 속도 ↑** (긴 컨텍스트 처리 시간 감소)

**5축 토큰 절약 전략**:

| 축 | 효과 |
|---|---|
| **명령어 3종** (`/usage` `/compact` `/clear`) | 20-30% 절약 |
| **CLAUDE.md 룰북** | 20-30% 절약 (불필요 출력 차단) |
| **서브에이전트 위임** | 15-25% 절약 (메인 컨텍스트 보호) |
| **autocompact 조정** | 10-15% 절약 (주기적 압축) |
| **Skill 분할** | 5-10% 절약 (큰 작업 단위 분할) |

총합 **~73%** (중복 효과 반영).

💰 유료 필요: Claude Code Pro 이상
✅ 무료 대안: Codex / Gemini CLI / Ollama 로컬 일부 동일 패턴 적용 가능

## 따라하기

### 축 1. 토큰 절약 핵심 명령어 3종

**`/usage`** — 작업 전후

```
주간 사용량 + 세션 사용량 + 리셋 시간 한눈에 확인.
"이번 주 한도 30% 남았네" 같은 자기 통제 가능.
```

**`/compact`** — 긴 작업 도중

```
채팅 요약 진행 → 오래된 데이터 드롭 (스레드 문맥은 유지)
1시간 작업 중 30분 시점에 1회 실행 권장.
```

**`/clear`** — 작업 전환 시

```
완전히 깨끗한 세션 시작.
이전 디버깅 로그의 토큰 낭비 차단.
서로 무관한 작업 사이엔 반드시 /clear.
```

### 축 2. CLAUDE.md 룰북 적용

프로젝트 루트 또는 `~/.claude/CLAUDE.md`:

```markdown
# Response Style
- 응답은 간결하게. 불필요한 서문·요약 금지.
- 한 줄로 끝날 답변은 한 줄로만.
- 코드만 요청한 경우, 부연 설명 생략.

# Output Limits
- Bash output이 길 경우 head, tail, jq 등으로 잘라서 보여줄 것.
- 테스트 로그는 마지막 20줄만 분석.
- 파일 보여줄 때 1000줄 넘으면 청크 분할.

# Workflow
- 대규모 조사·분석은 서브에이전트로 위임.
- 메인 컨텍스트는 지휘·검토만.
- 단순 검색·확인은 메인에서 직접.

# Token Saving
- 코드 변경 후 변경된 부분만 보여줄 것 (diff 형태).
- 100줄 이상 새 파일 만들 때 사용자에게 미리 확인.
- 사용자가 명시하지 않은 추가 기능 자발 추가 X.
```

### 축 3. 서브에이전트 위임 패턴

**기본 원칙 3가지**:

| 원칙 | 의미 |
|---|---|
| **격리 작업** | 서브에이전트는 격리된 컨텍스트에서 작업 |
| **결과만 반환** | 진행 과정은 숨기고 **최종 결과만** 메인으로 |
| **파일로 저장** | 3개 이상 병렬 시 각 결과 **개별 파일** 저장 |

**🚨 Opus 비용 함정**:
- 서브에이전트는 **부모 모델 설정 상속** → Opus 모델 5개 병렬 = **비용 5배 폭증**
- **해결**: 단순 조사·크롤링은 명시적으로 `--model sonnet` 또는 `--model haiku` 지정

**위임 기준**:

| ✅ 위임 추천 | ❌ 위임 비추천 |
|---|---|
| 다중 모듈 조사 | 단일 검색 |
| 병렬 코드 리뷰 | 짧은 Lookup |
| 대규모 리팩토링 | 순차 의존성 작업 |
| 문서 양산 | 1-2턴 작업 |

### 축 4. autocompact 임계값 조정

`~/.claude/settings.json`:

```json
{
  "env": {
    "CLAUDE_AUTOCOMPACT_PCT_OVERRIDE": "70"
  }
}
```

| 작업 유형 | 권장 |
|---|---|
| 일반 작업 | **60~75%** |
| 매우 큰 컨텍스트 유지 필요 | 85% |
| 신중하게 다뤄야 할 디버깅 | 90% (압축 늦게) |

권장 시작: **70%** → 1주일 사용 후 본인 작업 패턴에 맞게 조정.

### 축 5. Skill 분할 (큰 작업 단위 분리)

**대규모 리팩토링 X** → **5개 단위 작업으로 분할**:

```
1차 세션: "auth 모듈만 리팩토링" + /goal lint clean and tests pass
   ↓ /clear
2차 세션: "API 모듈만 리팩토링" + /goal
   ↓ /clear
3차 세션: "DB 모듈만 리팩토링" + /goal
   ↓ /clear
...
```

이렇게 분할하면 각 세션이 **작은 컨텍스트 + 빠른 압축** → 토큰 누적 감소.

- **스타트업 CTO — 팀 토큰 사용 표준화** — 회사 `CLAUDE.md` 표준 룰북 배포 → 전 직원 동일 절약 효과. Enterprise 비용 30% 절감
- **프리랜서 개발자 — 클라이언트 다수 운영** — `/clear` 로 클라이언트별 세션 격리 + 서브에이전트 병렬 위임. 동시 5-10 클라이언트 처리

- **사내 강의 — AI 사용 표준화** — 위 7일 가이드를 사내 워크숍으로 운영 → 회사 AI 비용 줄이고 채용자 ROI 높임

## 주의사항

- **CLAUDE.md 룰북 과도 X** — "1줄로만 답해" 같은 강한 규제는 답변 품질 저하. **균형 필요**
- **`/clear` 는 복구 불가** — 진행 중 작업 도중 사용 금지. **작업 전환 시에만**
- **서브에이전트 Opus 폭주 비용** — 위임 시 반드시 모델 명시. 비용 5배 폭증 위험
- **autocompact 50% 이하 역효과** — 너무 자주 압축되면 작업 흐름 끊김. **60% 미만 비권장**
- **`/usage` 의존 — 정확도 100% 아님** — 일부 백그라운드 작업은 즉시 반영 X. 큰 결정에는 며칠치 평균 참고
- **토큰 절약 ≠ 품질 저하** — 절약만 추구하면 응답 품질 떨어짐. **품질 유지 + 절약 균형** 점검
- **장시간 압축된 세션은 환각 가능성 ↑** — 너무 압축된 컨텍스트는 정보 누락. 중요 작업은 새 세션 권장
