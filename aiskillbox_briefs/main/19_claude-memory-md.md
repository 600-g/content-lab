💡 이 스킬은 **Claude Code 의 `MEMORY.md` 자동 메모리 시스템 200줄 법칙**으로, AI 가 매 세션마다 스스로 학습한 사용자 패턴·선호도·반복 명령어를 단축 형태로 기억하게 만드는 셰프의 개인 노트 활용법입니다.

## 이게 뭔가요?

**`MEMORY.md` = Claude Code 의 자동 메모리 시스템 핵심**. 셰프가 주방에서 일하며 개인적으로 적어두는 **자동 메모리(Auto Memory) 파일**.

**MEMORY.md 의 4가지 핵심 속성**:

### 1. 저장 위치 및 성격

- **경로**: `~/.claude/projects/<프로젝트해시>/memory/`
- 프로젝트 폴더에 **겉으로 드러나지 않음**
- 팀원과 공유(Git 체크인)하는 `CLAUDE.md` 와 달리, **사용자 개인 전용** 파일 (Git 공유 불가)

### 2. 똑똑한 자동 기록 방식

- **AI 자체 판단**: 사용자가 일일이 적어주지 않아도, Claude 가 작업하며 발견한 유용한 패턴·반복 명령어·선호도를 스스로 파악 → **백그라운드 자동 저장**
- **자연스러운 지시**: "우리는 npm 대신 pnpm을 쓴다고 기억해" / `/memory` 명령어 → AI 가 알아서 요약 기록

### 3. 가장 중요한 원칙 — "첫 200줄의 법칙"

> **매 세션 시작 시 Claude 는 `MEMORY.md` 의 첫 200줄까지만 자동으로 읽어 들임**.

이는 AI 의 **작업대(컨텍스트 윈도우)** 공간 낭비 방지가 목적.

**관리 팁**: 내용이 길어지면 모든 것을 `MEMORY.md` 에 담지 말고, 같은 폴더 안에 `debugging.md` 같은 **토픽 파일로 분리**. 기본 200줄만 항상 기억하고, 디버깅 등 특정 작업 시에만 해당 토픽 파일을 추가로 꺼내 읽음.

### 4. `CLAUDE.md` 와의 한눈 비교

| 구분 | `CLAUDE.md` (주방 운영 매뉴얼) | `MEMORY.md` (셰프의 개인 노트) |
|---|---|---|
| **작성 주체** | 사용자가 직접 작성 | **Claude 가 자동 작성** (또는 사용자 지시) |
| **로드 시점** | 매 세션 시작 시 **전체 로드** | 매 세션 시작 시 **첫 200줄만 로드** |
| **주요 용도** | 프로젝트 아키텍처·코딩 컨벤션·핵심 규칙 | 작업 중 학습된 패턴·명령어·사용자 선호도 |
| **팀 공유** | Git 체크인 가능 | Git 체크인 불가 (개인 맞춤형) |

💰 유료 필요: Claude Pro 이상 권장 (Free 는 컨텍스트 제한)
✅ 무료 대안: 없음 (Claude Code 전용 시스템)

## 따라하기

### STEP 1. MEMORY.md 위치 확인

```bash
ls ~/.claude/projects/
# 프로젝트별 해시 폴더가 보임 (예: -Users-yourname-Developer-my-app)

cat ~/.claude/projects/<프로젝트해시>/memory/MEMORY.md
```

### STEP 2. 자연스럽게 학습시키기

작업 중 Claude 에게 자연어로 직접 알려주는 방식:

```
✅ "우리는 npm 대신 pnpm 쓴다고 기억해"
✅ "이 프로젝트는 항상 TypeScript strict 모드야"
✅ "테스트는 vitest 로 돌리고 jest 는 안 써"
✅ "PR 브랜치는 feature/<title> 형식으로 만들어줘"
✅ "/memory" 명령어로 명시적 기록
```

Claude 가 자동으로 `MEMORY.md` 에 요약·정리.

### STEP 3. 200줄 초과 시 토픽 파일로 분리

| 토픽 | 파일명 | 들어갈 내용 |
|---|---|---|
| **디버깅 패턴** | `debugging.md` | 자주 만나는 에러 + 해결법 |
| **테스트 패턴** | `testing.md` | 테스트 전략, mock 패턴 |
| **빌드 / CI** | `deployment.md` | 배포 명령어, CI 설정 |
| **DB 작업** | `database.md` | 마이그레이션, 쿼리 패턴 |
| **API 통합** | `apis.md` | 외부 API 호출 패턴 |

분리 후 `MEMORY.md` 는 **인덱스 + 가장 자주 쓰는 패턴** 만. 다른 건 필요할 때만 Claude 가 추가 로드.

### STEP 4. 주기적 점검 (월 1회)

```bash
# MEMORY.md 줄 수 확인
wc -l ~/.claude/projects/<프로젝트해시>/memory/MEMORY.md

# 200줄 가까우면:
# 1) 오래된 항목 제거
# 2) 토픽 파일로 분리
# 3) 비슷한 항목 통합
```

### STEP 5. 효과적인 메모리 만들기 5가지 패턴

1. **"왜" 를 함께 기록** — "X 를 쓴다"보다 "X 를 쓴다 (이유: Y 때문)" 가 6개월 뒤 본인이 이해 가능
2. **부정형 명시** — "Z 는 절대 쓰지 마라" 처럼 **금지 사항** 도 기록
3. **반복 명령어 단축형 등록** — "테스트는 `pnpm test --filter=core` 로" 같은 반복 패턴
4. **사용자 선호 톤** — "에러 메시지는 한글로", "코드 주석 최소화" 같은 스타일
5. **프로젝트 변천사** — "이전엔 X 썼다가 Y 로 마이그레이션 완료" 같은 히스토리

## 활용 예시

- **개인 개발자 — 사이드 프로젝트 컨텍스트 유지** — 매 세션 처음부터 설명할 필요 X. Claude 가 패키지 매니저·테스트 도구·코딩 컨벤션 다 기억
- **회사 프로젝트 — 사내 컨벤션 자동 적용** — `CLAUDE.md` (공유) + `MEMORY.md` (개인) 분리로 팀 컨벤션과 본인 개인 선호 모두 반영
- **시니어 개발자 — 디버깅 자산화** — 자주 만나는 에러 → `debugging.md` 에 누적. 6개월 뒤 신입 후배에게 그 파일 통째로 공유 가능
- **프리랜서 — 클라이언트별 컨텍스트 격리** — 클라이언트 A·B·C 각각 다른 프로젝트 폴더 → 각각 독립된 MEMORY.md. 컨텍스트 충돌 없음
- **언어 학습자·연구자** — Claude 와 학습 중 자주 묻는 주제를 자동 기록. 본인의 학습 진도가 메모리에 누적
- **콘텐츠 크리에이터** — 본인 글쓰기 톤, 자주 쓰는 비유, 금지 표현 다 메모리화. AI 가 본인 톤으로 일관되게 글 작성
