# 클로드 코드 창 간 메시지 주고받기

💡 클로드 코드 창(세션)끼리 **직접 메시지를 주고받는** 기능입니다. 2.1.224 버전부터 사용 가능합니다.

## 이게 뭔가요?

클로드 코드 창(세션)끼리 직접 메시지를 주고받을 수 있는 기능입니다. 이 기능은 Claude Code CLI 버전 2.1.224 (2026년 8월 7일 공개)부터 지원됩니다. 이를 통해 개발자들은 여러 클로드 코드 세션 간의 소통을 원활하게 하여 작업 효율성을 높일 수 있습니다.

본 기능은 별도의 활성화 절차가 필요 없으며, 특정 버전 이상만 충족되면 자동으로 사용 가능합니다. 다만, 현재는 맥(macOS) 및 리눅스 환경에서만 지원되며, 윈도우는 미지원 상태입니다. WSL 2 환경에서는 사용 가능합니다.

💰 유료 필요: Claude Code CLI 설치 및 사용
✅ 무료 대안: 별도의 무료 대안은 없으나, Claude Code CLI 자체는 무료로 제공됩니다.

## 따라하기

1.  **사용 가능 여부 확인**:
    *   맥 또는 리눅스 환경인지 확인합니다.
    *   터미널에 `claude --version`을 입력하여 현재 설치된 클로드 코드 버전을 확인합니다.
    *   버전이 2.1.224 이상인지 확인합니다. 만약 버전이 낮다면, 클로드 코드를 최신 버전으로 업데이트한 후 다시 확인합니다.
    *   채팅창에 `/list-agents` 명령어를 입력했을 때, 현재 접속 가능한 에이전트(창) 목록이 뜨면 기능이 정상적으로 활성화된 것입니다. 별도의 설정 없이 즉시 사용할 수 있습니다.

2.  **메시지 주고받기**:
    *   **명령어 없이 요청**: "옆 창에 마이그레이션 끝났는지 물어봐 줘" 와 같이 자연어로 요청하면 됩니다.
    *   **특정 창 지정**: 여러 창이 열려 있을 경우, "결제 쪽 작업하던 창에 알려줘" 와 같이 구체적으로 설명하면 클로드가 해당 창을 찾아 메시지를 전달합니다.
    *   **별명 설정**: 자주 사용하는 창에는 `/rename` 명령어를 사용하여 별명을 붙여두면, 나중에 해당 창을 더 쉽게 지목할 수 있습니다.

3.  **알아두면 좋은 명령어**:
    *   `/list-agents` (=`/peers`): 현재 메시지를 주고받을 수 있는 창(에이전트) 목록을 확인합니다.
    *   `/rename`: 현재 세션 창에 사용하기 쉬운 별명을 붙입니다.
    *   `/status`: 현재 사용 중인 창의 메시지 주소(Peer address)를 확인합니다.

## 활용 예시

1.  **코드 변경 사항 공유**: "A 브랜치 관련 수정 사항 옆 창에 요약해서 보내줘" 라고 요청하면, 현재 창의 변경 사항을 요약하여 다른 클로드 코드 창으로 보낼 수 있습니다.
    *   *입력 예시*: "이 함수에 대한 설명을 옆 창에 보내줘"
    *   *결과*: 지정된 창으로 해당 함수의 설명이 텍스트로 전달됩니다.

2.  **작업 진행 상황 알림**: "모든 테스트 통과했으니 다음 단계 진행해도 돼" 라고 동료의 클로드 코드 창에 알림을 보낼 수 있습니다.
    *   *입력 예시*: "데이터베이스 마이그레이션 완료했어. 다음 작업 요청해도 좋아."
    *   *결과*: 지정된 창에 메시지가 도착하여 작업 상태를 알립니다.

3.  **코드 리뷰 요청**: "이 부분 코드 리뷰 요청해" 라고 말하여, 다른 클로드 코드 창에서 특정 코드 블록에 대한 리뷰를 요청할 수 있습니다.
    *   *입력 예시*: "이 코드 블록을 검토해줄 수 있니?"
    *   *결과*: 해당 코드 블록과 함께 리뷰 요청 메시지가 다른 창으로 전달됩니다.

## 주의사항

*   **메시지 권한**: 받은 메시지는 해당 창에서 직접적인 권한 승인이나 설정 변경에 사용될 수 없습니다. 명령어를 적어 보내도 텍스트로만 전달되어 보안을 강화합니다.
*   **권한 확인 건너뛰기 모드**: `bypassPermissions` 모드로 실행 중인 창에 메시지를 보내면, 수신 측에서 확인 절차를 거치게 됩니다. 5분 내에 승인되지 않으면 메시지는 자동 폐기됩니다.
*   **텔레메트리 설정**: `DISABLE_TELEMETRY`와 같이 텔레메트리 비활성화 설정이 켜져 있으면 이 메시지 기능도 함께 꺼질 수 있습니다. 기능이 보이지 않는다면 이 설정을 먼저 확인해야 합니다.
*   **컨테이너 환경**: 도커(Docker)와 같은 컨테이너 내부 세션과 외부 세션 간에는 서로 메시지를 주고받을 수 없습니다.
*   **무한 핑퐁 방지**: 두 창이 서로에게 무한히 메시지를 주고받는 경우, 시스템은 이를 감지하여 자동으로 통신을 차단합니다.
