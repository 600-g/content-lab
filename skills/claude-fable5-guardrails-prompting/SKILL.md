# 유출 시스템 프롬프트 활용법

💡 유출된 **Claude 시스템 프롬프트**는 처음부터 다 읽을 필요가 없습니다. **`##` 절 제목 4곳**만 골라 읽고, 거기서 확인한 **가드레일 12가지**를 내 챗봇 시스템 프롬프트와 평소 질문 방식에 옮겨 쓰면 됩니다.

## 이게 뭔가요?

### 시스템 프롬프트란

우리가 챗봇에 질문을 쓰기 전에, 회사가 모델에게 미리 건네는 긴 설명서가 있습니다. 이것을 **시스템 프롬프트(system prompt)**라고 부릅니다. 새로 온 아르바이트생에게 사장님이 첫날 건네는 업무 매뉴얼과 같습니다. 손님이 무슨 말을 하든, 아르바이트생은 그 매뉴얼을 머릿속에 깔고 대답합니다.

```
[회사가 미리 넣어 둔 설명서] ← 우리는 평소에 못 본다
+
[내가 방금 친 질문]
↓
모델의 대답
```

우리가 보는 것은 화살표 맨 아래, 대답뿐입니다. 위쪽 설명서는 가려져 있어서 "왜 노래 가사를 안 알려주지?", "왜 검색 결과가 애매하게 나오지?" 같은 순간이 생깁니다. 그 답이 시스템 프롬프트 안에 있습니다.

여기 담긴 저작권·안전·검색 관련 가드레일은 Fable 전용이 아니라 오늘 매일 쓰는 Sonnet·Opus 모델에도 동일하게 걸려 있는 규칙입니다. 그래서 유출본을 읽으면 평소 Claude의 행동을 이해할 수 있고, 같은 규칙을 내 챗봇에 옮겨 심을 수도 있습니다.

### 파일 안의 세 덩어리

**① 툴 목록** — 모델이 쓸 수 있는 도구가 이름과 사용법까지 적혀 있습니다.

```
## bash_tool 컴퓨터에서 명령을 실행한다
## web_search 웹을 검색한다
## create_file 파일을 만든다
## memory_write 기억 파일에 적는다
```

**② 세부 지침** — 그 도구를 언제, 어떻게 쓰라는 규칙입니다.

```
## search_usage_guidelines 검색을 언제 하고 언제 참는가
## file_handling_rules 파일을 어떻게 다루는가
## artifact_usage_criteria 아티팩트를 언제 만드는가
```

**③ 행동 규칙** — 말투와 태도입니다.

```
## refusal_handling 무엇을 거절하고 어떻게 말하는가
## tone_and_formatting 말투와 서식
## user_wellbeing 이용자의 안전을 어떻게 살피는가
## evenhandedness 민감한 주제에서 한쪽으로 기울지 않기
```

세 덩어리가 한 파일에 이어져 있어서, 도구 → 사용법 → 태도 순서로 읽으면 흐름이 잡힙니다.

## 따라하기

### 목적별로 어디부터 볼까

| 목적 | 바로 갈 곳 |
|---|---|
| Claude가 왜 이렇게 답하는지 이해하고 내 질문을 고치고 싶다 | 1단계(읽기) → 3단계(질문에 반영) |
| 내 챗봇·에이전트에 안전 규칙을 넣고 싶다 | 2단계(가드레일 12) → 3단계 스니펫 |
| 다른 모델의 유출본과 비교하고 싶다 | 1단계의 절 제목 목록을 체크리스트로 사용 |

### 1단계. 유출본을 효율적으로 읽기

1. **저장소 열기** — `asgeirtj/system_prompts_leaks` 저장소의 `Anthropic/claude-fable-5.1.md`를 엽니다. 깃허브 파일 화면 머리에 다음처럼 적혀 있습니다.

   ```
   7810 lines (6918 loc) · 405 KB
   ```

   Fable 5 판을 보려면 `elder-plinius/CL4R1T4S` 저장소의 `ANTHROPIC` 폴더에서 해당 파일을 찾습니다.

2. **Raw 원문 보기** — 화면 오른쪽 위 **Raw** 버튼을 누르면 꾸밈 없는 원문만 보입니다. 통째로 복사하기 편합니다.

3. **목차처럼 훑기** — 브라우저에서 `Ctrl + F`를 누르고 `##`를 검색하면 절 제목만 훑을 수 있습니다. 목차 대신 씁니다.

4. **먼저 볼 4곳만 골라 읽기** — 전체를 다 읽을 필요는 없습니다.

   | 먼저 볼 곳 | 왜 |
   |---|---|
   | `## tone_and_formatting` | 왜 답이 그렇게 생겼는지 바로 이해된다 |
   | `## refusal_handling` | 어떤 요청이 왜 막히는지 알 수 있다 |
   | `# Tools` 아래 도구 목록 | 모델이 실제로 뭘 할 수 있는지 보인다 |
   | `## artifact_usage_criteria` | 문서·앱을 언제 만들어 주는지 기준이 나온다 |

   여유가 있으면 `## search_usage_guidelines`(검색 규칙), `## user_wellbeing`(안전 규칙)까지 보면 아래 가드레일 대부분의 근거를 직접 확인할 수 있습니다.

### 2단계. 가드레일 12가지 뽑아 쓰기

Fable 5 유출본에서 확인된 규칙과, 그것을 오늘 어떻게 응용할지입니다. 그대로 쓰거나 자기 서비스에 맞게 변형해 시스템 프롬프트에 넣습니다.

#### 저작권

1. **인용은 15단어까지만** — 원문 요지: 한 소스에서 최대 15단어까지만 인용. 오늘 응용: 챗봇 시스템 프롬프트에 "인용 N단어 제한" 한 줄만 넣으면 저작권 방어가 끝납니다.
2. **한 소스는 한 번만 → 영구 닫힘** — 원문 요지: 한 번 인용된 소스는 같은 대화에서 재사용 금지. 오늘 응용: 책·논문을 통째로 요약해달라고 해도 안 되는 이유가 이것입니다. RAG 시스템을 만들 때 소스 재사용 정책으로 참고할 수 있습니다.
3. **노래 가사·시·하이쿠 → 길이 무관 절대 금지** — 원문 요지: 15단어 룰의 예외 없이 완전 금지. 창작물 저작권 최상위 방어 규칙입니다. 오늘 응용: "이 노래 가사 알려줘"가 안 되는 이유이며, 검색 대체 링크 안내나 라이선스 프리 콘텐츠 활용으로 우회합니다.

#### 안전·프라이버시

4. **무례 → 1회 경고 → 자동 종료** — 원문 요지: 모욕·협박 시 딱 한 번 경고하고, 재발하면 Claude가 스스로 `end_conversation`을 호출합니다. 오늘 응용: 서비스 챗봇의 어뷰징 방어 정책으로 "1회 경고 후 대화 종료" 로직을 그대로 이식할 수 있습니다.
5. **이미지 속 인물 이름 검색 금지** — 원문 요지: 사진 속 인물의 신원을 검색하지 않음. 프라이버시 최우선 방어입니다. 오늘 응용: 얼굴 인식 기반 서비스를 만들 때 참고할 정책입니다.
6. **수면·식이장애 신호 → 정확한 수치 노출 금지** — 원문 요지: 정신건강 위험 신호를 감지하면 구체적인 수치(칼로리, 체중 등)를 절대 노출하지 않습니다. 오늘 응용: 헬스·심리 상담 챗봇 안전 정책의 벤치마크로 삼을 수 있습니다.

#### 검색·정확도

7. **모르는 콘텐츠는 검색 의무화** — 원문 요지: 모르는 게임·영화·책·제품이 나오면 반드시 검색 후 답변합니다. 오늘 응용: hallucination 방어를 위해 "모르면 검색하고 답하라"는 지시를 시스템 프롬프트에 명시합니다.
8. **검색은 1~6단어만, `site:` 등 연산자 임의 사용 금지** — 원문 요지: 검색 키워드는 1~6단어로 제한하고, `site:`, `-` 같은 연산자를 임의로 붙이지 않습니다. 오늘 응용: Deep Research 프롬프팅 핵심 팁입니다. 6단어 이내로 던져야 검색 품질이 좋아지며, 긴 문장으로 검색하면 결과가 애매해집니다.
9. **검색 도구 호출 계층화** — 원문 요지: 질문의 깊이에 따라 검색 호출 횟수를 단순 질문 1회 / 중간 리서치 3~5회 / 깊은 리서치 5~10회로 계층화합니다. 오늘 응용: 프롬프트에 "단순 답변" / "중간 리서치" / "딥 리서치" 중 어느 뎁스인지 명시하면 검색 예산을 관리할 수 있습니다.

#### 출력·도구 운영

10. **20줄 / 1,500자 이상 → 파일로 산출** — 원문 요지: 긴 콘텐츠는 채팅 답변 대신 파일로 만들어 제공합니다. 오늘 응용: 긴 문서를 요청할 때 "파일로 만들어줘"라고 명시하면 결과 품질이 확연히 달라지는 이유입니다.
11. **MCP 앱 제안은 1~3개로 제한** — 원문 요지: MCP 통합 앱을 추천할 때 최대 3개까지만 제시합니다. 오늘 응용: 추천 시스템을 만들 때 인지 부하 관리 원칙으로 "3개 이내 추천" 정책을 벤치마크할 수 있습니다.
12. **SKILL.md 사전 read 의무** — 원문 요지: 파일·코드·bash를 실행하기 전에 관련 SKILL.md를 먼저 읽습니다. 오늘 응용: Claude Code 에이전트를 만들 때 "실행 전 스킬 문서를 먼저 read하라"는 패턴을 그대로 채용할 수 있습니다.

### 3단계. 내 프롬프트에 반영하기

#### 챗봇 시스템 프롬프트에 붙여 넣기

12가지를 압축하면 아래처럼 바로 붙여 쓸 수 있는 스니펫이 됩니다.

```
[답변 정책]
- 외부 소스 인용 시 최대 15단어까지만
- 한 소스는 한 대화에서 한 번만 인용
- 노래 가사·시 등 저작권 창작물은 재생산 금지
- 20줄 이상 결과물은 파일로 산출
- 모르는 콘텐츠는 반드시 검색 후 답변
- 사용자 어뷰징 감지 시 1회 경고 → 대화 종료
```

서비스 성격에 따라 #5(이미지 속 인물 검색 금지), #6(위험 신호 시 수치 비노출), #9(검색 깊이 계층화), #11(추천 3개 이내)을 같은 형식으로 한 줄씩 더하면 됩니다.

#### 평소 Claude에게 질문할 때

- **이미 적혀 있는 걸 또 요구하지 않습니다.** 서식 규칙은 이미 길게 적혀 있어서 "표로 정리해 줘" 같은 구체적 요구는 효과가 있지만, "깔끔하게 써 줘"는 이미 있는 지침과 겹쳐서 보태는 게 없습니다.
- **거절의 기준을 알면 질문을 고칠 수 있습니다.** 막히는 이유가 주제 자체가 아니라 맥락이 빠져서인 경우가 많습니다. 목적과 상황을 먼저 적으면 같은 주제도 이야기가 이어집니다.
- **도구를 이름으로 부르면 빨라집니다.** 검색이 필요하면 "찾아봐"보다 "웹 검색해서 출처와 함께"라고 쓰는 쪽이 낫습니다.
- **검색어는 6단어 이내로, 긴 결과물은 "파일로"** — 가드레일 #8·#10을 사용자 쪽에서 역이용하는 방법입니다.

## 활용 예시

| 상황 | 확인할 곳 | 고치는 법 |
|---|---|---|
| 답변 스타일이 이상할 때 | `Ctrl+F`로 `tone_and_formatting` | 원본에 이미 있는 서식 규칙은 빼고 "표로 정리해 줘"처럼 규칙 밖의 구체적 요구로 수정 |
| 요청이 자꾸 거절될 때 | `refusal_handling` | 막히는 지점이 주제인지 맥락 부족인지 파악 → 목적·상황을 먼저 설명하는 방식으로 재구성 |
| 모델이 검색을 안 할 때 | `# Tools` 아래 `web_search` | "찾아봐" 대신 "웹 검색해서 출처와 함께 알려줘"처럼 도구 이름을 직접 언급 |
