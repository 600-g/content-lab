# AI로 매매 계획 검토 자동화

💡 이 스킬은 **클로드 코드**와 **GPT-6 아스트라**를 붙여 「주문은 사람이, 검토는 AI가」 하는 매매 계획 검토 파이프라인을 6개 프롬프트로 구축하는 스킬입니다. AI는 시장 자료를 정리해 **승인/관망/기각**으로만 정리하고, 실제 주문은 절대 자동으로 넣지 않습니다.

## 이게 뭔가요?

혼자 매매를 결정하는 사람 옆에 **검토 담당**을 하나 붙여 두는 구조입니다. 식당으로 비유하면 주방장이 요리를 내기 전에 누군가 한 번 보는 것과 같습니다 — 간은 맞는지, 문제가 있는지. 이 검토 담당은 요리를 직접 하지 않습니다. 내보내도 되는지만 판단합니다.

이 스킬에서 AI(GPT-6 아스트라)는 시장을 보고 → 괜찮아 보이는 자리를 골라 → 계획을 써 보고 → 위험한지 따져 보고 → 「승인 / 관망 / 기각」 셋 중 하나로 정리해 주는 역할만 합니다. 주문을 넣는 건 끝까지 사람입니다. AI는 증권사에 연결되어 있지 않고, 자료는 사람이 직접 붙여 넣어야 하며, 자동 실행과 서버를 따로 붙이지 않으면 사람이 돌릴 때만 작동합니다.

**하는 일**: 붙여 준 자료 정리, 눈여겨볼 자리 선별, 진입·목표·손절 표 작성, 규칙 위반 시 차단, 승인/관망/기각 정리.
**안 하는 일**: 자료를 스스로 가져오지 않음, 「오른다」는 예측을 하지 않음, 숫자대로 실제 주문을 넣지 않음, 규칙을 대신 정하지 않음, 버튼을 누르지 않음.

작업 도구는 **클로드 코드**(작업을 돌리는 자리)와 **GPT-6 아스트라**(생각하는 쪽)를 함께 씁니다. GPT-6 아스트라가 없으면 ✅ 무료 대안으로 Gemini나 ChatGPT 무료 버전으로도 동일한 프롬프트를 그대로 돌릴 수 있습니다. 시세 자료·차트 도구는 본인이 쓰는 서비스를 그대로 쓰면 됩니다.

## 따라하기

### 1. 준비물 확인

| 무엇 | 왜 필요한가 | 필수 여부 |
|---|---|---|
| 클로드 코드 | 이 작업을 돌리는 자리 | 필수 |
| GPT-6 아스트라 (또는 대체 LLM) | 생각하는 쪽 | 필수 |
| 시세 자료 | 가격·거래량·주요 가격대 | 필수 |
| 모의투자 계좌 | 가짜 돈으로 먼저 해 보기 | 필수 |
| 차트 도구 | 눈으로 보고 알림 걸기 | 있으면 좋음 |
| 표 (엑셀·구글 시트) | 자리와 결과를 쌓아 두기 | 있으면 좋음 |
| 자동 실행 + 서버 | 진짜 24시간 돌리려면 | 선택 |

### 2. 폴더 만들기 (5분)

클로드 코드를 새 폴더에서 열고 아래 구조를 만듭니다.

```
내프로젝트/
├── data/     ← 시세 자료를 넣는 곳
├── setups/   ← 만든 매매 계획을 두는 곳
└── logs/     ← 결과를 쌓는 곳
```

볼 종목과 시간 단위를 먼저 정합니다 (예: 다섯 종목만, 1시간 봉). 많이 보면 좋아 보이지만 반대입니다 — 적게 봐야 제대로 봅니다. 자료를 `data/`에 넣고 아래 여섯 지시문을 순서대로 돌립니다. **모의투자로만 하고, 판단은 전부 기록해 둡니다.**

### 3. 프롬프트 ① 훑기 — 시장 스캐너

```
아래는 내가 보는 종목들의 자료다.
[가격 · 거래량 · 추세 · 주요 가격대 · 관련 뉴스를 여기 붙여넣기]
종목마다 이렇게 정리해 줘.
- 지금 추세가 어느 쪽인가
- 거래량에 눈에 띄는 게 있나
- 더 볼 만한가, 아닌가
⚠️ 내가 준 자료만 써라. 가격이나 뉴스를 지어내지 마라.
빠진 자료가 있으면 「이게 없다」고 말해 줘.
```

### 4. 프롬프트 ② 신호 — 볼 만한 자리 고르기

```
방금 정리한 내용에서 «볼 만한 자리»를 뽑아 줘.
돌파 · 눌림 · 탄력 · 추세 지속 · 반전 다섯 갈래로 나눠서.
자리마다 이렇게 적어 줘.
- 왜 그렇게 보는지 (근거)
- 뭐가 나오면 맞는 건지 (확인 조건)
- 뭐가 나오면 아닌 건지 (무효 조건)
⚠️ 이건 «될 수도 있는 자리»지 «해야 하는 거래»가 아니다.
그 점을 문장에 그대로 써 줘.
```

### 5. 프롬프트 ③ 계획 — 매매 계획 짜기

```
[종목 이름] 의 이 자리를 계획으로 만들어 줘.
- 방향 (사는 쪽인가 파는 쪽인가)
- 진입 조건 (어떤 모양이 나오면 들어가나)
- 목표 (어디서 받나)
- 손절 (어디서 끊나)
- 무효 조건 (어디가 깨지면 계획을 버리나)
- 시간 단위
- 손익비 (잃을 1에 벌 얼마)
- 왜 이 자리인지 한 줄
애매한 말 말고 «이 값이면 이렇게» 로 적어 줘.
모의투자용 계획이다.
```

### 6. 프롬프트 ④ 리스크 — 막는 자리

```
계좌 [금액] 원, 한 번에 걸 수 있는 최대 [1] % 로 본다.
진입 [값], 손절 [값] 일 때 이걸 계산해 줘.
- 몇 주 / 몇 개를 담아야 하나
- 그러면 잃을 수 있는 돈은 얼마인가
그리고 이걸 확인해 줘.
- 지금 들고 있는 것까지 합친 총 노출
- 시장이 평소보다 심하게 흔들리는지
- 내가 정한 최대 손실 폭을 넘는지
⚠️ 하나라도 내 규칙을 넘으면 «차단» 이라고 분명히 말하고 계획을 막아 줘.
```

### 7. 프롬프트 ⑤ 감시 — 판이 바뀌었나

```
지금 보고 있는 종목과 걸어 둔 계획이다.
[새 자료를 여기 붙여넣기]
- 지난번과 뭐가 달라졌나
- 들어갈 조건이 나왔나, 아니면 무효가 됐나
- 위험 쪽은 아직 괜찮나
- 종목 목록에서 뺄 것과 넣을 것
- 어디에 알림을 걸어 두면 좋은가
⚠️ 앞으로 어떻게 될지는 말하지 마라. 바뀐 것만 말해 줘.
```

### 8. 프롬프트 ⑥ 결정 — 최종 메모

```
지금까지 나온 걸 한 장으로 정리해 줘.
- 자리 요약
- 신호가 얼마나 센가
- 위험은 어느 정도인가
- 매매 계획 (진입 · 손절 · 목표 · 손익비)
- 최종 상태: 승인 / 관망 / 기각 — 그리고 그 이유
⚠️ 마지막에 이 문장을 그대로 넣어 줘.
「모의투자용이며, 사람이 확인해야 합니다. 판단과 책임은 사용자에게 있습니다.」
```

### 9. 매매 계획 / 리스크 점검 / 결정 메모 서식

들어가기 전에 아래 서식을 다 채웁니다. 들어간 다음에 채우면 변명이 됩니다.

```
종목:
방향:
진입:
목표:
손절:
무효 조건:
시간 단위:
손익비:
이 자리로 본 이유:
```

승인으로 넘어가기 전 통과해야 하는 리스크 점검 다섯 개입니다. 하나라도 걸리면 계획을 막습니다.

| 무엇을 보나 | 어떻게 정하나 |
|---|---|
| 1. 담는 크기 | 한 번에 걸 돈을 «잃어도 되는 금액»에서 거꾸로 계산 |
| 2. 총 노출 | 지금 들고 있는 것까지 다 합쳐서 확인 |
| 3. 낙폭 | 계좌가 고점에서 얼마나 내려왔는지, 선을 넘으면 쉼 |
| 4. 출렁임 | 평소보다 심하게 흔들리면 위험이 커짐 |
| 5. 최대 손실 | 하루/한 주 한도를 넘으면 그날은 끝 |

최종 결정 메모 서식:

```
자리 요약:
신호 세기:
위험도:
매매 계획:
최종 상태: 승인 / 관망 / 기각
>> 사람이 확인해야 합니다 <<
```

### 10. 감시 루프 반복

전체 흐름은 훑기 → 신호 → 리스크 → 감시 → 알림 → (다시 훑기)로 돌아가는 순서입니다. 이 순서는 **반복할 수 있는** 순서일 뿐 **저절로 도는** 순서가 아닙니다. 손으로 돌리면 돌릴 때만 작동합니다. 진짜로 밤에도 돌게 하려면 정해진 시간마다 자동 실행되는 예약 실행과, 꺼지지 않는 서버(노트북이 아닌) 두 가지를 별도로 붙여야 합니다. 이걸 안 붙였으면 자는 동안 아무도 봐 주고 있지 않다고 생각해야 합니다.

## 활용 예시

- 다섯 종목, 1시간 봉만 보기로 정하고 `data/`에 가격·거래량·뉴스를 붙여넣은 뒤 프롬프트 ①~⑥을 순서대로 돌리면 → 각 종목별로 승인/관망/기각이 붙은 결정 메모 5장이 `logs/`에 쌓입니다.
- 프롬프트 ④ 리스크 단계에서 "계좌 1000만원, 최대 1%"로 입력했더니 → AI가 진입가·손절가 기준 몇 주를 담을 수 있는지 계산하고, 총 노출이 한도를 넘으면 "차단"이라고 답합니다.
- 다음 날 새 시세 자료를 프롬프트 ⑤에 붙이면 → "지난번 무효 조건이 깨져서 이 종목은 목록에서 뺄 것을 권함" 같은 변화만 알려주고 향후 전망은 말하지 않습니다.

## 주의사항

- AI는 증권사에 연결되어 있지 않으며 주문을 넣지 않습니다. 승인이 나와도 실제 주문은 사람이 직접 눌러야 합니다.
- 실제 돈으로 바로 하면 안 됩니다. 모의투자로 먼저 충분히 반복하세요.
- AI가 내는 숫자는 틀릴 수 있습니다. 프롬프트 ①에서 "내가 준 자료만 써라, 지어내지 마라"고 명시했더라도 사람이 다시 확인해야 합니다.
- API 키 등 열쇠는 코드에 적지 말고 `.env` 파일에 두고, 그 파일은 저장소에 올리지 않습니다.
- 손실 한도는 "적당히"가 아니라 숫자로 정해야 리스크 점검이 의미가 있습니다.
