# 키미 K3 제대로 쓰는 법

💡 AI 모델 **K3**를 제대로 활용하는 방법을 안내하는 스킬입니다. 설정부터 결과 향상을 위한 요청법, 다양한 강점별 프롬프트 활용법을 포함합니다.

## 이게 뭔가요?
키미(Kimi.ai)는 한국어에 특화된 AI 모델로, 특히 K3 모델은 이전 모델 대비 성능 향상을 제공합니다. 이 가이드는 키미 K3의 기본 설정부터 고급 활용법까지 체계적으로 안내하여 사용자가 AI의 잠재력을 최대한 이끌어낼 수 있도록 돕습니다.

공식 가이드 내용과 실제 사용자들의 경험을 바탕으로 구성되어 있어 실질적인 도움을 받을 수 있습니다. 처음 키미를 접하는 사용자부터 기존 사용자까지 모두에게 유용한 정보를 제공합니다.

💰 **유료 필요**: 일부 고급 기능이나 API 사용 시 유료 플랜이 필요할 수 있습니다. 하지만 기본적인 웹/앱 사용은 무료로도 충분히 가능합니다.
✅ **무료 대안**: 웹 인터페이스(kimi.ai) 및 무료 앱(iOS, Android, 데스크톱)을 통해 기본적인 기능은 무료로 사용할 수 있습니다.

## 따라하기

**1. 기본 설정 확인**
*   **모델 선택**: 채팅창 상단의 모델 선택에서 **K3**가 활성화되어 있는지 반드시 확인합니다. 기본 모델이 이전 모델로 설정되어 있을 경우, 모르고 다른 모델을 사용하게 될 수 있습니다.
*   **로그인**: 한국 사용자는 `kimi.ai`로 접속하여 구글 계정으로 로그인합니다. 결제 정보 입력 없이도 사용 가능합니다.
*   **기기 연동**: 휴대폰 앱도 같은 계정으로 로그인하면 웹에서의 대화 기록이 연동됩니다.

**2. 키미 접근 방법**
*   **웹**: `kimi.ai`에서 대부분의 작업을 수행할 수 있습니다.
*   **모바일 앱**: iOS, 안드로이드, 하모니OS 지원.
*   **데스크톱 앱**: 윈도우 및 애플 실리콘 맥용 앱 제공 (문서 작업, 대시보드 등).
*   **터미널**: 코딩용으로, 폴더째 다룰 때 유용합니다. API 키를 발급받아 사용합니다.

**3. 무료 한도**
*   무료 사용 한도는 고정된 수치가 없으며 상황에 따라 변동됩니다. 아래 가이드라인을 지키면 체감 사용량이 달라집니다.

**4. 무엇을 시킬지 막막할 때 (콘텐츠 아이디어)**
*   **게임**: 오픈월드 3D 게임, 격투 액션, 레이싱, 보물찾기.
*   **분해/구조**: 총기, 카메라, 시계 등 부품 분해 (제품 소개, 교육 자료).
*   **개념 시각화**: 블랙홀, 로켓, 토성, 해양, 미시세계 등 추상적 개념 시각화.
*   **3D 랜드마크**: 런던, 콜로세움, 경기장 등 3D 모델링.
*   **UI/UX**: 천이 흔들리는 패브릭, 타자기 타건 등 손맛이 필요한 화면 구현.
*   **제품 소개**: 제품 소개 페이지 초안 (문구, 화면 구성).

**5. 결과가 달라지는 요청법**
*   **완료 조건 명확화**: 구체적인 지시보다 **무엇이 되면 끝나는지**를 명확히 하고 방법은 AI에게 맡깁니다.
    *   예: "이 주제로 보고서 초안을 완성해줘" (X) → "상반기 운영 보고서 초안을 **완성**해줘. **분기별 매출 추이 그래프를 포함**하고, **프로젝트 일정은 타임라인으로 요약**해줘." (O)
*   **역할 부여**: "너는 오래 해온 **[무슨 일] 하는 사람**이야"와 같이 역할을 부여하면 답변의 깊이가 달라집니다.
    *   예: "너는 **20년 경력의 마케팅 전문가**야."
*   **자료/조건/결과 분리**: 태그를 사용하여 자료, 조건, 원하는 결과를 명확히 구분합니다.
*   **긍정형 요청**: "~하지 마"보다 "**~해줘**"와 같은 긍정형 요청이 더 효과적입니다.
*   **형식 지정**: 글자 수보다 **문단 수**나 **목록 형태**로 지정하고, **예시**를 제공하면 그대로 따릅니다.

**6. 키미의 강점: 코드와 실제 화면을 오가며 다듬기**
*   **실행 화면 캡처 활용**: 결과물을 받은 후, **실행한 화면을 캡처하여 다시 입력**합니다. AI는 눈으로 보이는 것을 기반으로 더 정확하게 수정합니다.
    *   **프롬프트 예시**: `[방금 나온 결과를 실행해서 찍은 화면 캡처 첨부] 이게 지금 실제로 보이는 화면이야. <고칠 것> - [화면에서 어색한 부분]을 [원하는 모습]으로 <조건> - 나머지 부분은 그대로 두고 전체 파일을 다시 줘`
*   **이미지 기반 요청**: 원하는 화면과 비슷한 **이미지를 첨부**하여 색감, 여백, 그림자 등을 맞춰달라고 요청합니다.
    *   **프롬프트 예시**: `[원하는 느낌에 가까운 화면 이미지 1장 첨부] 이 이미지를 참고 삼아 아래를 만들어줘. <만들 것> - [무엇을 하는 화면인지] <참고 기준> - 색과 여백과 글자 크기 비율은 이미지에 맞춰줘 - 이미지에 없는 요소는 임의로 넣지 말고 목록으로 따로 알려줘 </참고 기준>`

**7. 템플릿 프롬프트 (대괄호 `[ ]`만 수정)**

*   **단일 HTML 파일 생성 (프론트엔드 개발)**
    ```
    너는 프론트엔드를 오래 해온 개발자야.
    <만들 것>
    [무엇을 만들지 한 문장]
    <화면>
    - 처음 열면 [무엇]이 보임
    - [어떤 조작]을 하면 [어떤 반응]
    <조건>
    - 단일 HTML 파일 하나로 끝나게 해줘
    - 라이브러리가 필요하면 CDN으로 불러와줘
    - 휴대폰 세로 화면 기준으로 먼저 맞춰줘
    - 여기 적힌 기능만 넣어줘. 더 좋은 아이디어가 있으면 코드 대신 목록으로 알려줘
    <끝나고>
    실행 방법 한 줄과 내가 바꿔볼 만한 값 세 개를 알려줘
    ```

*   **긴 문서/코드 분석 (분석가 역할)**
    ```
    너는 이 분야 자료를 정리해온 분석가야.
    <자료>
    [문서나 코드를 통째로 붙여넣기 또는 파일 첨부]
    <해줄 것>
    1. 전체 구조를 섹션마다 한 줄로 요약해줘
    2. 서로 어긋나거나 빠진 부분을 위치와 함께 목록으로 정리해줘
    3. 내가 [하려는 일]을 하려면 어디부터 볼지 순서를 정해줘
    <조건>
    - 자료에 있는 내용만 사용하고 없는 건 없다고 표시해줘
    - 판단이 들어간 문장에는 근거가 된 원문을 그대로 인용해서 붙여줘
    ```

*   **이미지 기반 UI/UX 분석 및 HTML 생성 (디자이너 역할)**
    ```
    [이미지 첨부]
    너는 화면 구조를 뜯어보는 디자이너야.
    <해줄 것>
    1. 캡처에서 읽히는 구조를 위에서 아래 순서로 정리해줘
    2. 색과 글자 크기 규칙을 표로 만들어줘
    3. 같은 구조에 내 내용을 넣은 단일 HTML 파일을 만들어줘. 내용은 [내 소재]
    <조건>
    - 로고와 상표는 자리만 비워두고 그대로 따라 만들지 마
    - 캡처에 있는 요소만 사용해줘
    - 추측한 부분이 있으면 마지막에 어디를 추측했는지 알려줘
    ```

*   **장기 작업 (프로젝트 담당자 역할)**
    ```
    너는 이 일을 끝까지 책임지는 담당자야.
    <목표>
    [끝났을 때 어떤 상태여야 하는지]
    <지금 있는 것>
    [가진 자료나 코드]
    <완료 기준>
    [무엇이 되면 끝난 것으로 볼지]
    <진행 방식>
    - 시작 전에 계획을 다섯 줄 안으로 보여주고 바로 이어서 진행해줘
    - 중간에 판단이 필요하면 스스로 정하고 진행한 다음 마지막에 무엇을 왜 그렇게 정했는지 알려줘
    - 단계마다 무엇을 했는지 한 줄씩 남겨줘
    - 끝나면 남은 문제와 다음에 할 일을 목록으로 정리해줘
    ```

**8. 발표 자료(슬라이드) 생성**
*   키미는 슬라이드 제작 기능이 있습니다. 주제만 던지기보다 요청을 세 덩어리로 나누어 주는 것이 중요합니다.

    *   **1. 문서의 기본 정보**: 몇 장짜리 무슨 문서인지 명확히 지정합니다.
        *   예: "20장짜리 상반기 운영 보고서"
    *   **2. 내용 규칙**: 어떤 항목을 어떤 형태로 바꿀지 구체적으로 지정합니다.
        *   예: "숫자는 그래프로, 일정은 타임라인으로, 관계는 도해로"
    *   **3. 스타일**: 결과물의 전체적인 디자인 톤을 지정합니다. 업계 표준 서식이나 세계관 비유를 활용할 수 있습니다.
        *   **업계 표준**: "글로벌 컨설팅사 제안서 서식으로" 또는 "대형 유통사 영업부서 표준 서식으로"
        *   **세계관 비유**: "성장 지표를 게임 레벨업으로 환산하고 화면도 그 미술로 맞추는 쪽"

*   **프롬프트 예시 (업계 표준)**
    ```
    20장짜리 <상반기 운영 보고서> 슬라이드를 만들어줘.
    <내용 규칙>
    - 매출과 비용은 분기별 막대 그래프로
    - 프로젝트 일정은 타임라인 한 장으로
    - 조직과 역할 관계는 도해 한 장으로
    - 장마다 핵심 문장 한 줄을 제목 아래 넣어줘
    </내용 규칙>
    <스타일>
    - 글로벌 컨설팅사 제안서 서식. 여백 넉넉하게, 색은 두 가지 안쪽으로
    </스타일>
    ```

*   **프롬프트 예시 (세계관 비유)**
    ```
    25장짜리 <올해 팀 성과 공유> 슬라이드를 만들어줘.
    <내용 규칙>
    - 매출 성장은 "영토 확장"으로, 신규 고객은 "동료 영입"으로 바꿔서 표현해줘
    - 팀별 투입 가능 인력은 체력 게이지로, 예산은 자원 아이콘 개수로
    - 분기는 사계절 배경으로 나눠줘
    </내용 규칙>
    <스타일>
    - 도트 그래픽 게임 화면. 아이콘과 표도 같은 결로
    </스타일>
    ```

**9. 긴 자료 처리 팁**
*   한 번에 넣기 어려운 긴 자료는 **섹션별로 먼저 요약을 만든 후, 그 요약들을 다시 모아서 질문**합니다. 앞선 내용이 이어져야 하는 경우, 앞 섹션 요약을 함께 제공합니다.

**10. 과한 결과물 방지 (모호한 지시 주의)**
*   AI는 지시가 모호하면 **알아서 과하게 처리**하는 경향이 있습니다. "적당히 알아서 해줘"와 같은 요청은 예상치 못한 기능까지 추가될 수 있습니다. 따라서 프롬프트에는 **넣을 것을 정확히 적고, 추가 아이디어는 코드 대신 목록으로 요청**하는 것이 좋습니다.

**11. 결과물 수정 방법**
*   결과가 마음에 들지 않을 때, 처음부터 다시 시키기보다 다음 세 가지 방법으로 구체적인 수정을 요청합니다.
    1.  **[고치고 싶은 부분]만 바꿔줘. 나머지 코드는 그대로 유지한 채로 전체 파일을 다시 줘.**
    2.  **실행했더니 이 오류가 났어. 원인을 한 줄로 짚고 고친 전체 파일을 다시 줘. [오류 메시지 붙여넣기]**
    3.  **기능과 구조는 그대로 두고 보기 좋게만 다듬어줘. 여백을 넉넉히 하고 제목과 본문 크기 차이를 키우고 색은 두 가지 안쪽으로 정리해줘.**

**12. 터미널에서의 키미 활용 (코딩)**
*   **API 키 사용**: 키미 코드 콘솔에서 API 키를 발급받아 기존 코딩 에이전트에 연결하여 사용할 수 있습니다. 복수의 파일 작업이나 장기 작업에 유리합니다.
*   **키미 자체 터미널 도구**: 무료로 공개된 키미 자체 터미널 도구를 설치하여 사용할 수 있습니다. (설치 방법 아래 참고)
    ```bash
    # 맥 · 리눅스
    curl -fsSL https://code.kimi.com/kimi-code/install.sh | bash

    # 윈도우
    irm https://code.kimi.com/kimi-code/install.ps1 | iex
    ```
*   **화면 녹화 활용**: 말로 설명하기 어려운 동작은 화면을 녹화하여 입력하면 AI가 이를 보고 따라 합니다.
*   **계획 모드**: 파일을 건드리기 전에 계획을 먼저 세우는 모드를 활용하여 엉뚱한 방향으로 수정되는 것을 방지할 수 있습니다.
*   **설정 파일 대화 연동**: 외부 도구 연동 시 설정 파일을 직접 열지 않고 대화로 설정할 수 있습니다.
*   **IDE 연동**: Zed, JetBrains 계열 편집기에서 바로 사용할 수 있습니다.

**13. 간단한 HTML 파일 생성 (초보자용)**
*   코드를 복사하여 메모장에 붙여넣고 파일 이름 끝에 **.html**을 붙여 저장한 후 더블클릭하면 브라우저에서 열립니다.


## 💡 아이디어
*   **수익화**: 특정 산업 분야(예: 법률, 의료, 금융)의 전문 용어에 특화된 Kimi 프롬프트 템플릿을 유료로 제공하거나, 기업 맞춤형 AI 에이전트 구축 컨설팅 서비스와 연계.
*   **프로젝트 강화**: Kimi API를 활용하여 개인 프로젝트(예: 블로그 자동 글쓰기, 코드 스니펫 생성 도구, 발표 자료 자동화 툴)를 개발하고, 이를 오픈소스 커뮤니티에 공유하며 사용자 피드백을 통해 기능 개선.
*   **교육 콘텐츠**: Kimi의 다양한 활용 사례를 담은 온라인 강의 또는 워크숍을 개설하여 사용자의 AI 활용 능력을 향상.

## 주의사항
*   **모호한 지시 금지**: "적당히 알아서 해줘"와 같은 모호한 지시는 AI가 과도하게 반응하게 만들어 예상치 못한 결과를 초래할 수 있습니다. 구체적인 목표와 제약을 명확히 설정해야 합니다.
*   **무료 한도 변동**: 무료 사용 한도는 고정되어 있지 않으며, 상황에 따라 변동될 수 있으므로 사용 시 주의가 필요합니다.
