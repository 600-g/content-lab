# AI 에이전트 세션 간 메시지 전송 및 관리

💡 이 스킬은 **Claude Code CLI**를 활용하여 여러 **AI 세션** 간에 메시지를 정확하게 전달하고, 세션의 **이름(agentName)**과 **상태**를 체계적으로 관리하는 방법입니다.

## 이게 뭔가요?
이 스킬은 여러 개의 AI 세션(예: 메일 처리, 콘텐츠 기획, 협업 등)을 동시에 띄워놓고 작업할 때, 각 세션 간에 정보를 정확하게 전달하는 방법을 다룹니다. 단순히 내용을 복사하여 붙여넣는 것을 넘어, 한 세션의 결과물을 다른 세션의 맥락 위에 얹어 작업하는 것이 핵심입니다. 

이 과정에서 가장 큰 난관은 AI가 인식하는 **세션의 이름(agentName)**과 **창에 보이는 제목(customTitle)**이 다를 수 있다는 점입니다. 또한, 세션 간의 이름 충돌, 공백 처리, 그리고 세션의 생명주기(종료, 재개)를 이해해야만 안정적으로 작업을 수행할 수 있습니다. 이 기능은 **Claude Code CLI**를 통해 제어되며, **Mac/Linux 환경**에서 주로 사용됩니다.

💰 유료 필요: 해당 기능은 Claude Code CLI를 사용하며, 사용량에 따라 비용이 발생할 수 있습니다. ✅ 무료 대안: 현재는 CLI 사용이 필수적이며, 다른 무료 툴로는 세션 간의 정교한 메시지 전달 및 상태 관리가 어렵습니다.

## 따라하기

### 1. 세션 이름 및 주소 확인하기
가장 먼저, AI가 인식하는 세션의 **진짜 이름(agentName)**을 확인해야 합니다. 단순히 터미널 탭에 적은 이름은 AI가 인식하는 이름과 다를 수 있습니다. 

- **전체 세션 목록 확인:**
```bash
claude agents --json
```

- **스크립트용 목록 추출:**
```bash
claude agents --json | python3 -c "import json,sys;[print(a.get('name')) for a in json.load(sys.stdin)]"
```

이 명령어를 통해 AI가 인식하는 **`agentName`**을 파악하는 것이 중요합니다. 

### 2. 세션 이름 지정 및 열기
세션을 열 때 원하는 이름을 지정하는 것이 기본입니다. 

- **세션 이름 지정:**
```bash
claude -n <원하는_이름>
```

- **세션 재개 (이어가기):**
```bash
claude -r <세션ID> -n <원하는_이름>
```

**주의:** `-r`과 `-n`은 서로 다른 개념입니다. `-n`은 이 창의 이름을 정하는 것이고, `-r`은 이어갈 대화의 맥락을 지정합니다. 

### 3. 세션 이름 변경하기
세션이 열린 후 이름을 변경할 때는 **`/rename`** 명령어를 사용해야 합니다. 

- **세션 내부에서 실행:**
```
/rename <새로운_이름>
```

이 명령어는 창 제목뿐만 아니라 **멘션 주소(agentName)**까지 변경합니다. 

### 4. 세션 간 메시지 전송하기
특정 세션으로 메시지를 보내려면 **`@`** 기호를 사용하고, **`agentName`**을 정확히 입력해야 합니다. 

- **메시지 전송 예시:**
`@<세션이름> 여기에 내용을 보내세요.`

### 5. 세션 정리 및 관리
작업이 끝난 세션은 반드시 정리해야 이름 충돌을 막을 수 있습니다. 

- **세션 종료:**
```bash
claude stop <세션ID>
```

- **모든 세션 목록 확인:**
```bash
claude agents --all
```

## 활용 예시

### 시나리오 1: 메일 확인 후 협업 세션으로 정보 인계
1. **메일 세션**에서 내용을 확인합니다. (예: `mail` 세션)
2. **메일 세션**에서 다음 명령어를 입력합니다:
   `@협업 세션에 이 내용을 넘겨봐`
3. **결과:** 전송된 메시지는 단순 텍스트가 아니라, **핵심 항목이 표로 정리**되고, **원문 식별자**가 붙으며, **확인 필요 지점**까지 분석되어 전달됩니다. 

### 시나리오 2: 세션 이름 충돌 방지
같은 이름으로 세션을 이어 열 경우, **새로 뜬 세션이 이름을 양보**받아 자동 이름이 부여됩니다. 이 경우, 원래 세션이 여전히 그 이름을 점유하고 있어, `@`로 호출하면 **작업 중인 세션이 아닌 옛날 껍데기 세션**으로 메시지가 전송될 수 있습니다. 이 문제를 방지하려면, 이름을 재사용할 옛 세션부터 `claude stop <id>`로 명시적으로 닫아야 합니다.

### 시나리오 3: 세션 상태 확인
어떤 세션이 현재 작업 중인지, 아니면 대기 중인지 확인하려면 다음 명령어를 사용합니다. 

```bash
claude agents --json | python3 -c "import json,sys;[print(a.get('name'),a.get('status','-')) for a in json.load(sys.stdin)]"
```

- **`busy`**: 현재 작업 중인 세션
- **`idle`**: 입력을 기다리는 세션
- **`blocked`**: 프로세스가 죽었거나 멈춘 세션 (로그 확인 필요)

## 주의사항

- **이름 규칙:** 세션 이름은 **공백 없이** 짓는 것이 가장 안전합니다. 공백이 포함된 이름은 `@` 자동완성 목록에 나타나지 않거나, 이름 뒤의 공백이 문장으로 인식되어 매칭에 실패할 수 있습니다.
- **이름 충돌:** 세션 이름은 컴퓨터 내에서 **유일**해야 합니다. 이름이 겹치면 새로 뜬 세션이 이름을 양보받게 되며, 이로 인해 의도치 않은 세션으로 메시지가 전송될 수 있습니다.
- **`--fork-session`의 오해:** `--fork-session`은 **개명 수단이 아닙니다.** 이는 대화 내용을 **복사**하여 새 세션을 만드는 기능이며, 원본 세션은 그대로 남아있습니다. 이름만 바꾸고 싶다면 반드시 `/rename`을 사용해야 합니다.
- **백그라운드 세션:** 현재 실행 중인 백그라운드 세션은 `-r` 명령어로 직접 이어받을 수 없습니다. 이 경우 `--fork-session`을 사용해야 합니다.
- **오래된 세션:** 대화 기록이 오래된 세션을 재개할 경우, 사용량 제한에 대한 경고가 뜨며, **요약본으로 재개할지** 여부를 선택해야 합니다.
