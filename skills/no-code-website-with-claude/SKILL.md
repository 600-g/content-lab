# 코딩 없이 Claude로 웹사이트

💡 웹사이트가 안 나오는 이유는 실력이 아니라 **순서**입니다. Claude 에 **8단계 프롬프트를 같은 대화창에서 차례로** 넣어 한 페이지 사이트를 만들고, **Supabase·GitHub·Vercel·Cloudflare** 무료 플랜으로 실제 주소에 올립니다.

## 이게 뭔가요?

디자이너도 개발자도 없이, 채팅창에 준비된 프롬프트를 순서대로 넣고 대괄호 `[ ]` 만 내 사업에 맞게 채우면 **나만의 웹사이트**가 나오는 방법입니다. 같은 원리로 숫자 데이터를 보여주는 **웹 대시보드**, 인스타 프로필용 **링크인바이오** 페이지도 만들 수 있고, 무료 도구 조합으로 **서버 비용 없이** 배포까지 이어집니다.

핵심은 **순서**입니다. Claude 에 "내 사업 웹사이트 만들어줘"라고 한 번에 던지면 밋밋한 결과가 나옵니다. 사람이 실제 사이트를 만들 때처럼 **방향 → 첫 화면 → 신뢰 → 상품 소개 → 망설임 해소 → 행동 유도** 순으로 문구를 쌓고, 마지막에 그 전부를 넘겨 **HTML 한 파일**로 바꿉니다. Claude 는 복잡한 지시를 이해해 구조화된 결과물을 만드는 데 강해서, 사용자는 방향을 정하고 마음에 드는 걸 고르기만 하면 됩니다.

### 어떤 방법을 언제 쓰나

| 만들고 싶은 것 | 쓸 방법 | 도구 | 비용·시간 |
|---|---|---|---|
| 사업 소개·랜딩·포트폴리오 한 페이지 | 방법 1. 8단계 프롬프트 | Claude | 무료로 시작 가능 |
| 링크인바이오(링크 모음 + 방문자 수집·알림) | 방법 1 응용 → 방법 3 배포 | Claude (+ Slack Webhook) | 무료로 시작 가능 |
| 매출 같은 내 숫자를 보여주는 공유용 대시보드 | 방법 2. 자동화 대시보드 | Claude + Supabase + GitHub + Vercel | 무료(신용카드 불필요) · 첫 대시보드 1~2시간, 이후 20분 |
| 로그인·DB·통계가 있는 웹 서비스, 사이드 프로젝트 MVP | 방법 3. 무료 배포 스택 | Next.js + Supabase + Firebase + Cloudflare Pages/Vercel | 서버비 0원 (규모 커지면 유료 전환 가능) |

**도구 역할 한눈에 (집 짓기 비유)**

| 부품 | 역할 | 쓰는 것 |
|---|---|---|
| 목수 | 집을 지어주는 사람 | Claude |
| 집 | 숫자·내용을 보기 좋게 그리는 것 | HTML 파일 하나 (서비스라면 Next.js) |
| 창고 | 숫자를 보관하는 곳 | Supabase (무료 DB·인증) |
| 택배함 | 집 설계도(코드)를 보관 | GitHub |
| 주소 | 남들이 찾아올 수 있게 | Vercel 또는 Cloudflare Pages |
| 방문 기록 | 사용자 행동 분석·통계 | Firebase (GA4 기반 애널리틱스) |

💰 **유료 필요**: 모든 도구가 무료 플랜으로 시작 가능하지만, 서비스 규모가 커지거나 무료 한도를 넘거나 상업적 용도로 확장하면 유료 전환이 필요할 수 있습니다. 특히 **Vercel 무료 플랜은 상업적 사용이 제한될 수 있습니다.**
✅ **무료 대안**: 도구 자체가 무료 조합입니다. 다른 무료 티어로 바꾸고 싶다면 데이터베이스는 PlanetScale, 인증은 Auth0 의 무료 티어를 고려할 수 있습니다.

## 따라하기

### 방법 1. 8단계 프롬프트로 한 페이지 웹사이트 만들기

**준비물은 Claude 하나입니다.** claude.ai 에서 새 대화를 열고 아래 프롬프트를 ①번부터 순서대로 넣습니다. Claude 가 앞 대화를 기억하므로 **같은 창에서 이어서 하는 것**이 핵심입니다.

진행 방식: 하나 넣고 답을 받은 다음 → 마음에 안 드는 부분만 구체적으로 고쳐달라고 하고 → 다음 단계로 넘어갑니다. 잘 진행되면 쓰는 시간보다 고르는 시간이 더 길어집니다.

**① 웹사이트 전체 방향 설정** — 제일 먼저, 딱 한 번. 여기서 잡은 방향이 나머지 7개를 다 끌고 갑니다.

```
너는 브랜드 웹사이트를 오래 만들어온 전략가야. 나는 [내 사업 한 줄 설명]을 하는 사람이고, [어떤 고객]을 대상으로 웹사이트를 하나 만들려고 해. 이 사이트에서 방문자가 하길 바라는 딱 한 가지 행동은 [예: 상담 신청 / 구매 / 문의]야. 먼저 이 웹사이트의 전체 방향을 잡아줘. 어떤 톤이 맞는지, 섹션을 어떤 순서로 두면 좋은지, 첫 화면에 와야 할 핵심 한 문장은 뭔지. 화려한 말 말고, 이 고객이 실제로 반응할 방향으로.
```

**② 홈 첫 화면 문구** — 3초 안에 붙잡기. 첫 화면에서 못 잡으면 아래는 안 읽힙니다. 제목 후보를 3개 뽑아달라고 해서 고르세요.

```
방금 잡은 방향을 기준으로, 홈 첫 화면 문구를 써줘. 방문자가 3초 안에 "내 얘기다" 싶게. 큰 제목 한 줄, 그 아래 설명 한 줄, 버튼에 들어갈 문구 하나. 내 사업이 남들과 다른 점 한 가지가 그 제목에 꼭 들어가야 해.
```

**③ 신뢰 섹션** — "이 사람 믿어도 되겠다". 없는 실적을 만들면 안 됩니다. 가진 게 적으면 적은 대로, 진짜만 씁니다.

```
이 웹사이트에 넣을 신뢰 섹션을 써줘. [경력 / 해온 횟수 / 실제 후기 중 내가 내세울 수 있는 것]을 근거로, 짧은 신뢰 문구 3개. 없는 숫자는 절대 지어내지 말고 내가 실제로 가진 것만으로. 처음 온 사람이 안심할 정도면 충분해.
```

**④ 상품/서비스 소개** — "우리는 이런 기능이 있어요"가 아니라 "당신이 이렇게 편해져요"로.

```
내 [상품 / 서비스]를 소개하는 섹션을 써줘. 항목마다 이게 뭔지 한 줄, 이걸로 고객에게 뭐가 좋아지는지 한 줄. 기능 자랑 말고 고객이 얻는 결과 중심으로. 항목은 [개수]개로.
```

**⑤ 망설임 해소(사전 답변)** — 대부분 이 섹션이 없어서 놓칩니다. 반론을 먼저 눌러주는 게 전환의 절반입니다.

```
내 고객이 결제나 신청 직전에 망설이는 이유 5개를 뽑아줘. "비싸다" "나한테 맞을까" "지금 꼭 해야 하나" 같은 속마음. 그리고 각각을 웹사이트에서 미리 풀어주는 문장을 써줘. 방문자가 묻기 전에 페이지가 먼저 대답하게.
```

**⑥ 최종 행동 유도** — 맨 아래를 그냥 "문의하기"로 두면 아깝습니다. 여기가 마지막 설득 구간입니다.

```
페이지 맨 아래 마지막 행동 유도 섹션을 써줘. 여기까지 읽은 사람이 [원하는 행동]을 지금 하게. 짧은 제목 한 줄, 미루면 아쉬운 이유 한 줄, 버튼 문구 하나. 압박하지 말고, 지금 하는 게 낫다는 느낌만.
```

**⑦ HTML 웹사이트 코드 생성** — 문구를 페이지로. 여기서 코드 한 덩어리가 나옵니다.

```
지금까지 나온 문구 전부야: [①~⑥에서 받은 문구를 여기에 다 붙여넣기] 이걸 실제로 열리는 웹사이트 한 페이지로 만들어줘. HTML 한 파일로, 스타일까지 넣어서. 색 분위기는 [예: 차분한 남색 / 따뜻한 베이지 / 깔끔한 흰색], 폰트는 읽기 편한 걸로. 휴대폰에서도 안 깨지게.
```

**⑧ 검토 및 수정** — 의심 많은 손님의 눈. 오래 들여다볼수록 내 눈엔 안 보이는 걸 잡아줍니다.

```
이 웹사이트를 처음 보는, 의심 많은 방문자라고 생각하고 전체를 봐줘. 무슨 사이트인지 5초 안에 이해돼? 안 믿기는 문장, 어색한 부분, 빼도 되는 군더더기를 짚어줘. 그리고 딱 3가지만 고치라면 뭐야? 그 3가지는 바로 반영해줘.
```

**⑦에서 나온 코드 띄우기**

1. Claude 가 만든 페이지는 대화 안에서 바로 미리보기가 됩니다.
2. 마음에 들면 코드를 복사해 메모장에 붙여넣고 파일 이름을 `index.html` 로 저장합니다.
3. 더블클릭하면 내 컴퓨터에서 열립니다.
4. 실제 주소로 올리려면 이 `index.html` 파일 하나만 무료 호스팅에 올립니다 → 방법 3 의 Cloudflare Pages 나 Vercel 을 쓰면 됩니다.

#### 응용: 링크인바이오 페이지

링크인바이오도 한 페이지 사이트라서 같은 흐름으로 만듭니다. 유료 링크인바이오 서비스에 의존하지 않으니 **디자인 자유도가 높고**, Claude 의 코딩 능력으로 단순 링크 모음을 넘어 **방문자 데이터 수집 → Slack 알림(Slack Webhook) → 방문자 분석**까지 붙일 수 있습니다.

1. ① 방향 설정에서 "방문자가 하길 바라는 딱 한 가지 행동"을 가장 중요한 링크 클릭으로 정합니다.
2. ②·④·⑥ 단계로 프로필 문구, 링크별 한 줄 설명, 맨 아래 행동 유도 문구를 받습니다.
3. ⑦ 단계에서 HTML 을 만들 때, 링크 클릭 기록·Slack Webhook 알림처럼 필요한 자동화를 함께 요청합니다.
4. 방법 3 으로 배포하면 외부 서비스 의존 없이 자체 호스팅되는 마케팅 도구가 됩니다. 방문 통계는 Firebase Analytics 로 볼 수 있습니다.

> Slack Webhook 주소 같은 비밀 값은 공개되는 HTML 에 그대로 넣지 않도록 주의합니다 (주의사항 참고).

### 방법 2. 자동화 대시보드 만들기 (Supabase + GitHub + Vercel)

비개발자도 내 숫자 데이터를 Supabase 에 저장하고, HTML/CSS/SVG 로 직접 그려, GitHub·Vercel 로 인터넷 주소에 공유하는 방법입니다. 구축 순서는 **창고(Supabase) → 집(HTML) → 택배함(GitHub) → 주소(Vercel)** 입니다.

#### 0단계 · 뭘 만드는지 그림부터

위 "도구 역할 한눈에" 표의 목수·집·창고·택배함·주소 구조를 먼저 이해합니다.

#### 1단계 · 계정 3개 만들기 (15분)

모든 계정은 무료이며 신용카드가 필요 없습니다. **반드시 GitHub 계정으로 나머지 두 개를 가입**해야 자동 배포가 원활합니다.

1. **GitHub**: 이메일로 가입
2. **Supabase**: Continue with GitHub 선택
3. **Vercel**: Continue with GitHub 선택

#### 2단계 · 창고 만들기 (20분)

1. **프로젝트 만들기**: Supabase 에 로그인 후 'New project' 를 클릭하고, 'Name' 은 `my-dashboard`, 'Region' 은 'Northeast Asia (Seoul)' 로 설정합니다. 데이터베이스 비밀번호는 반드시 메모장에 저장합니다.
2. **첫 번째 표 만들기 — 영업**: Supabase 의 SQL Editor 에 아래 SQL 을 붙여넣고 실행합니다. `[ ]` 안의 숫자는 실제 회사 데이터로 바꿉니다.

```sql
-- ① 월별 매출
create table sales_monthly (
  id bigint primary key generated always as identity,
  sort_order int not null,
  month text not null,
  revenue bigint not null,
  target bigint not null
);
insert into sales_monthly (sort_order, month, revenue, target) values
(1, '[2월]', [6200], [9200]),
(2, '[3월]', [6900], [9200]),
(3, '[4월]', [71
```

> ⚠️ 원 자료의 SQL 은 여기서 잘려 있습니다. 실행 전에 남은 행을 같은 형식 `(순번, '[월]', [매출], [목표])` 으로 채우고, 마지막 행 끝을 `;` 로 닫아야 오류가 나지 않습니다. 대괄호 `[ ]` 는 표시용이므로 실제 값만 남기고 지웁니다 (예: `(1, '2월', 6200, 9200),`).

#### 3~5단계 · 집 → 택배함 → 주소

원 자료의 이후 단계 본문은 전해지지 않아, 위 구조에 맞춘 연결 흐름만 정리합니다.

1. **집(HTML)**: Claude 에 Supabase 표 구조(`sales_monthly` 의 컬럼)를 알려주고, 이 표를 읽어 매출·목표를 HTML/CSS/SVG 로 그리는 한 파일짜리 대시보드를 요청합니다.
2. **택배함(GitHub)**: 만든 HTML 파일을 GitHub 저장소에 올립니다.
3. **주소(Vercel)**: Vercel 에서 그 저장소를 연결해 배포하면 공유 가능한 인터넷 주소가 생깁니다. GitHub 계정으로 가입해 두었기 때문에 저장소 연결이 바로 됩니다.
4. 이후 숫자는 Supabase 표만 고치면 대시보드에 반영되므로, 두 번째부터는 약 20분이면 끝납니다.

### 방법 3. 무료 배포 스택 — 서버비 0원으로 웹 서비스 올리기

1인 개발자나 사이드 프로젝트가 바이브코딩 등으로 만든 결과물을 혼자 간직하지 않고 실제 사용자에게 선보이기 위한 조합입니다. 무료 플랜의 한계를 잘 활용하면 상당한 수준의 서비스를 운영할 수 있습니다. 각 서비스의 세부 연동·설정은 해당 공식 문서를 참고합니다.

| 도구 | 역할 | 무료 포인트 |
|---|---|---|
| **Next.js** | 풀스택 웹 프레임워크 — 프론트엔드와 백엔드를 한 프로젝트에서 | 오픈소스 |
| **Supabase** | 무료 데이터베이스 및 인증 | API 요청 수에 대한 별도 과금 없음 |
| **Firebase** | 사용자 행동 분석·통계 | 애널리틱스 100% 무료, GA4 기반 보고서 |
| **Cloudflare Pages** | 무료 배포 플랫폼 | 하루 기준 100,000회 요청까지 무료 |
| **Vercel** | 무료 배포 플랫폼 (Next.js 개발사) | 설정 없이 빠른 배포, 단 상업적 사용 제한 확인 |

1. **Next.js 프로젝트 생성**

   ```bash
   npx create-next-app@latest my-app
   cd my-app
   ```

   방법 1·2 처럼 HTML 한 파일이면 이 단계는 건너뛰고 4번 배포로 갑니다.

2. **Supabase 설정**: 가입 후 프로젝트를 만들고, 데이터베이스 테이블을 설계하거나 필요하면 인증을 구성합니다.
3. **Firebase 설정**: Firebase 프로젝트를 만들고 사용자 행동 분석·통계 추적을 설정합니다. Google Analytics 연동 등을 활용할 수 있습니다.
4. **Cloudflare Pages 또는 Vercel 배포**: Git 저장소를 연결해 무료로 배포합니다.
   - **Cloudflare Pages**: Git 저장소를 연결하고 빌드 설정을 자동 감지하거나 수동으로 지정합니다. 트래픽 부담이 적고 상업적 프로젝트에 우선 고려합니다.
   - **Vercel**: Git 저장소를 연결하면 Next.js 프로젝트를 자동 감지해 배포합니다. 상업적 용도가 아니라면 좋은 선택입니다.
5. **연동 및 테스트**: 배포된 앱에서 Supabase·Firebase 기능이 정상 작동하는지 확인합니다.

### 배포 전 체크리스트

- [ ] 8단계는 같은 대화창에서 순서대로 진행했다 (건너뛴 단계 없음)
- [ ] 신뢰 섹션에 지어낸 숫자·후기가 없다
- [ ] ⑧ 검토 단계의 "3가지 수정"을 반영했다
- [ ] 휴대폰 화면에서 깨지지 않는다
- [ ] 상업적 프로젝트라면 Vercel 대신 Cloudflare Pages 를 우선 검토했다
- [ ] Supabase·Firebase·Cloudflare 무료 한도를 확인했다
- [ ] 공개되는 파일에 비밀번호·Webhook 주소 같은 비밀 값이 없다

## 활용 예시

**한 페이지로 충분한 사이트 (방법 1)**

| 유형 | 예 |
|---|---|
| 1인 서비스 | 코칭·컨설팅·과외 소개 페이지 — 전문성을 강조하고 상담 신청 유도 |
| 동네 가게 | 카페·공방·스튜디오 안내 — 감성적 분위기와 방문 예약 유도 |
| 제품 소개 | 상품 하나를 파는 랜딩 페이지 — 장점을 부각해 구매 전환 |
| 포트폴리오 | 내 작업을 보여주는 한 페이지 — 작업물 소개와 문의 유도 |
| 강의·모임 | 신청받는 클래스 안내 페이지 |
| 예약·문의 | 상담 신청받는 소개 페이지 |
| 링크인바이오 | 인스타 프로필 링크 페이지 — 방문자 수집·Slack 알림·분석까지 |

예: 정리 코칭이라면 첫 화면 제목 "바쁜 하루에도, 5분이면 정리되는 살림", 설명 "정리 초보도 오늘 바로 따라 하는 우리 집 정리 코칭", 버튼 "무료 상담 신청 →" 같은 결과가 나옵니다.

**데이터·서비스 (방법 2·3)**

- **매출 대시보드**: 월별 매출·목표를 Supabase 표에 넣고 Vercel 주소로 팀과 공유합니다.
- **개인 포트폴리오 웹사이트**: Next.js 로 만들고 Cloudflare Pages 에 무료 배포, Supabase 로 방명록·문의하기, Firebase Analytics 로 방문자 통계를 봅니다.
- **간단한 CRUD 서비스**: 인증이 필요한 메모장·할 일 목록, 또는 게시판이 있는 커뮤니티를 Next.js + Supabase(데이터베이스·인증)로 만들고 Vercel 무료 플랜으로 배포, Firebase 로 사용자 활동을 분석해 개선합니다.
- **사이드 프로젝트 MVP**: Next.js, Supabase, Cloudflare 로 초기 비용 없이 아이디어를 검증하고 Firebase 로 유입·행동 패턴을 분석합니다. 예를 들어 Next.js 로 AI 챗봇 UI 를 만들고 백엔드 로직은 Vercel Functions 등을 활용, Supabase 에 대화 기록을 저장하고 Firebase 로 사용량을 분석합니다.

## 💡 아이디어

- **단계적 수익화**: 무료 스택으로 출시해 사용자를 확보하고, 성장에 따라 유료 기능·광고·Pro 구독을 도입합니다. 필요한 부분만 유료 플랜으로 전환하며 확장하기 쉽습니다.
- **고도화 경로**: 무료 스택의 한계를 넘는 기능이 필요하면 각 서비스의 유료 플랜으로 점진적으로 올리거나 전문 솔루션으로 옮깁니다. 예를 들어 Supabase 데이터 용량 제한을 넘으면 RDS 같은 전문 DB 이전을 고려합니다.
- **한 번 만든 흐름 재사용**: 8단계 대화를 템플릿으로 저장해 두면 새 상품·새 이벤트 페이지를 같은 순서로 빠르게 찍어낼 수 있습니다.

## 주의사항

- **순서가 핵심**: 같은 대화창에서 위에서부터 차례로 넣어야 앞 단계의 방향과 문구가 이어집니다. 중간을 건너뛰면 결과가 붕 뜹니다.
- **영어로 넣을 필요 없음**: 프롬프트도 결과도 한국어로 충분합니다. 어색하면 "더 자연스럽게 다시 써줘"처럼 구체적으로 다시 요청합니다.
- **지어낸 실적 금지**: 신뢰 섹션의 숫자·후기는 실제로 가진 것만 씁니다.
- **Vercel 무료 플랜 상업적 사용 제한**: 상업적 프로젝트라면 Cloudflare Pages 를 우선 고려하거나 Vercel 유료 플랜을 검토합니다.
- **무료 한도 사전 확인**: Cloudflare 요청 수, Supabase 데이터베이스 크기·요청 수, Firebase 사용량 등 무료 티어 한도를 미리 확인하고 설계해야 예상치 못한 비용이나 서비스 중단을 막습니다.
- **비밀 값 보호**: Supabase 데이터베이스 비밀번호는 메모장에 따로 보관하고, 비밀번호·Slack Webhook 주소 같은 값은 누구나 볼 수 있는 HTML 이나 공개 저장소에 그대로 넣지 않습니다.
- **트러블슈팅**
  - Claude 결과가 밋밋하다 → ① 방향 설정을 건너뛰지 않았는지, 같은 대화창인지 확인합니다.
  - SQL 실행 오류 → 대괄호 `[ ]` 를 지웠는지, 마지막 행이 `;` 로 끝나는지 확인합니다.
  - Vercel·Supabase 연결이 꼬인다 → 두 서비스를 GitHub 계정으로 가입했는지 확인합니다.
  - 막히는 부분은 같은 작업을 하는 사람들과 오픈채팅방 등에서 정보를 나누면 빠르게 풀립니다.
