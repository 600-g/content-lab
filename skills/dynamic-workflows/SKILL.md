# Claude Code 자율·병렬 작업

💡 "Claude에게 일을 맡기고 내가 다른 일을 하자." 먼저 **병렬로 쪼갤 작업인지 판단**하고, 넓게 퍼뜨릴 일은 **다이내믹 워크플로우**, 끝날 때까지 반복할 일은 **/goal**, 여러 세션 감시는 **Agent View**로 처리합니다.

## 이게 뭔가요?

Claude Code에는 사람이 한 턴씩 지시하지 않아도 큰 작업을 스스로 굴리는 기능이 세 가지 있습니다.

- **다이내믹 워크플로우** — Claude가 즉석에서 JavaScript 스크립트를 작성하고, 백그라운드 런타임에서 실행해 대규모 작업을 오케스트레이션합니다. '넓이(병렬 분산)'를 위한 도구로, 반복적이고 깊이 있는 작업에 수십~수백 개의 에이전트를 동시에 투입해 교차 검증하는 데 최적화되어 있습니다. 런타임이 스크립트를 격리 실행하고 중간 결과는 대화 컨텍스트가 아닌 스크립트 변수에 저장하므로, Adversarial 에이전트들이 서로 결과를 검토해 논리적 결함을 걸러낸 뒤 최종 결과물만 세션으로 돌려줍니다. (Claude Code v2.1.154 이상, research preview)
- **`/goal`** — 완료 조건을 정해 두면 조건이 충족될 때까지 여러 턴을 자동 반복합니다. (Claude Code v2.1.139 이상)
- **Agent View (`claude agents`)** — 여러 세션을 한 화면에서 모니터링하는 통합 대시보드입니다. `/goal`과 함께 v2.1.139에 출시되었습니다.

여러 AI 에이전트를 조직도처럼 구성해 동시에 일을 처리시키는 방식을 커뮤니티에서는 **'그래프 엔지니어링'** 이라고 부릅니다. 개별 프롬프트를 순차 실행하는 대신 복수의 에이전트를 병렬로 돌려 속도와 효율을 올리는 것이 목표입니다. 하지만 잘못 쓰면 속도만큼 **실수도 증폭**됩니다. 그래서 이 문서는 "언제 병렬로 쪼갤지" 판단 기준 12가지를 먼저 세우고, 그다음 도구 사용법을 다룹니다.

### 직접 재본 결과 — 순차 vs 병렬

일곱 개의 작업 파일을 검수하는 작업을 두 방식으로 진행해 시간과 결과를 비교했습니다. 지시문은 거의 같았고 작업 방식만 달랐습니다.

| 구분 | 순차 방식 | 병렬 방식 |
|---|---|---|
| 소요 시간 | 5분 45초 | 3분 40초 |
| 토큰 | 적음 | 자릿수가 달라짐 |
| 결과 형태 | 서술형 심층 | 점수표 + 우선순위 |

병렬 처리로 시간은 줄었지만, 일부 결과에서 AI가 사실이 아닌 내용을 지어냈습니다. '개선안을 하나씩 달라'는 지시에 AI가 '없음'으로 끝내지 못하고 빈칸을 그럴듯하게 채워버린 것이 원인이었습니다. 병렬로 돌리면 속도뿐만 아니라 실수도 함께 증폭된다는 뜻입니다.

### 어떤 도구를 언제 쓰나

| 상황 | 쓸 도구 | 핵심 |
|---|---|---|
| 같은 종류의 독립 작업이 5개 이상 (찾기·판정·변환·수집) | 다이내믹 워크플로우 | 넓이 — N개를 에이전트에 나눠 동시 처리 + 교차 검증 |
| 작업 하나를 객관적 조건이 맞을 때까지 반복 (테스트 통과, 린트 통과) | `/goal` | 깊이 — 한 세션이 조건 충족까지 자동 반복 |
| 여러 세션을 동시에 띄워 두고 내 입력이 필요한 곳만 보고 싶다 | Agent View | 관제 — `s:blocked` 로 막힌 세션만 확인 |
| 창작·개인화·근거 없는 추론·앞 결과가 뒤 입력이 되는 작업 | 병렬 금지 → 일반 세션 순차 처리 | 병렬로 돌리면 지어낸 내용이 늘어남 |

## 따라하기

### 1단계 — 병렬로 쪼갤 작업인지 판단하기 (12가지 기준)

#### 병렬로 돌려도 되는 작업 (찾기, 판정, 변환, 수집)

1. **찾기**: 여러 파일이나 계정에서 특정 패턴이나 키워드를 검색하는 작업. 기존 데이터를 기반으로 하므로 지어낼 여지가 적습니다.
2. **판정**: 형식, 오탈자, 색상, 규격 등 기계적으로 체크 가능한 작업. 답이 명확하게 정해져 있습니다.
3. **변환**: 번역, 포맷 변경, 요약 등 원문이 존재해 나중에 대조가 가능한 작업.
4. **수집**: 여러 소스에서 정보를 긁어와 각각 정리하는 작업. 입력 데이터가 외부에 있어 AI가 임의로 생성할 여지가 적습니다.

#### 병렬로 돌리면 안 되는 작업 (창작, 개인화, 추론, 순차 의존)

5. **창작**: 없는 것을 새롭게 만들어야 하는 작업. AI가 빈칸을 임의로 채울 가능성이 높습니다.
6. **개인화**: 개인의 경험이나 의견이 필요한 작업. AI가 알 수 없는 정보를 지어낼 수 있습니다.
7. **추론**: 근거 없이 결론을 내려야 하는 작업. 에이전트마다 다른 결론을 낼 수 있습니다.
8. **순차 의존**: 앞선 결과가 뒤따르는 작업의 입력으로 쓰이는 경우. 본질적으로 병렬 처리가 불가능합니다. (이런 작업은 `/goal` 로 한 세션 안에서 반복시키는 편이 맞습니다.)

#### 실행 조건 (모두 만족할 때만)

9. **작업이 5개 이상일 것**: 작업 수가 적으면 병렬 처리의 이점보다 나누는 비용이 더 클 수 있습니다.
10. **개당 2~3분은 걸릴 것**: 짧은 작업 여러 개를 병렬로 처리하면 오버헤드가 더 많이 발생합니다.
11. **지시에 '개선안', '만들어줘' 등을 포함하지 말 것**: 창작을 유발해 오류의 원인이 됩니다.
12. **결과에 1인칭 문장이 있으면 전수 확인할 것**: AI가 본인의 경험인 것처럼 허위 정보를 생성할 수 있습니다.

### 2단계 — 다이내믹 워크플로우로 병렬 실행

#### 환경 설정 및 활성화

- **전제 조건**: Claude Code v2.1.154 이상 (research preview)
- **Max · Team 플랜**: 자동 ON, 별도 설정 불필요
- **Pro · Enterprise 플랜**: 기본 OFF. `/config` 에서 'Dynamic workflows' 토글을 켭니다. 또한 아래 「비활성화」에 나오는 설정(`settings.json` 의 `"disableWorkflows": true`, 환경 변수 `CLAUDE_CODE_DISABLE_WORKFLOWS=1`)이 남아 있으면 꺼진 채로 유지되므로 제거해야 합니다.

#### 실행

- **자연어 호출**: "run a workflow to..." 형식으로 입력합니다.
- **자동 트리거**: `/effort ultracode` 와 같이 특정 명령어를 입력해 전역 적용할 수 있습니다.
- **번들 기능**: `/deep-research <질문>` 처럼 특정 명령어로 시작할 수 있습니다.

일부 경우 Claude는 사용자가 명시적으로 요청하지 않으면 에이전트를 쓰지 않습니다. 프롬프트에 **'워크플로우를 사용하여'** 를 반드시 넣으세요. 1단계 기준을 반영한 복붙 프롬프트입니다.

```
워크플로우를 사용하여 아래 N개를 병렬로 처리해줘.
각 항목마다 독립적인 에이전트를 하나씩 할당하고, 마지막에 모든 결과를 합쳐줘.

[항목 목록]

각 항목마다:
[기계적으로 판정 가능한 지시]
해당 사항이 없으면 '없음'이라고만 쓰고 새로 만들지 마.
```

마지막 줄("해당 사항이 없으면 '없음'이라고만 쓰고 새로 만들지 마.")이 위 실험에서 빈칸을 지어낸 문제를 막는 장치입니다.

#### 제어 및 관리

- **`/workflows`**: 실행 목록을 확인하고 일시정지(`p`), 중지(`x`), 저장(`s`)을 할 수 있습니다. 에이전트별 토큰도 여기서 보고 언제든 중지합니다.
- **`/effort`**: 추론 강도 및 워크플로우 모드를 설정합니다.

#### 저장 및 재사용 (스킬처럼)

1. `/workflows` 메뉴에서 `s` 키를 눌러 현재 워크플로우를 저장합니다.
2. 저장된 워크플로우는 `/이름` 슬래시 커맨드로 호출하며, 인자 전달도 됩니다. (예: `/triage 1024, 1025, 1030`)

#### 비활성화

- `/config` 에서 'Dynamic workflows' 토글을 OFF 합니다.
- `settings.json` 파일에 `"disableWorkflows": true` 를 추가합니다.
- 환경 변수 `CLAUDE_CODE_DISABLE_WORKFLOWS=1` 을 설정합니다.

#### 결과에서 지어낸 내용 걸러내기

1. 결과에서 1인칭 문장('제가', '저는', '~했어요' 등)을 모두 찾습니다.
2. 찾은 문장이 실제로 사용자가 한 말인지 원본과 대조합니다.
3. 근거 없이 내려진 단정적인 문장을 의심합니다.
4. 여러 에이전트가 비슷한 문장을 생성했다면, 같은 빈칸을 각자 채운 것이므로 더욱 의심합니다.

### 3단계 — `/goal` 로 조건 달성까지 자동 반복

#### 목표 설정

```bash
/goal all tests in test/auth pass and the lint step is clean
/goal CHANGELOG.md has an entry for every PR merged this week
/goal all API endpoints return 200 or stop after 20 turns
```

목표가 활성화되면 입력창 옆에 `◎ /goal active` 가 표시됩니다.

#### 효과적인 조건 작성 원칙

- ✅ 객관적으로 검증 가능: `all tests pass`, `git status shows no uncommitted changes`
- ✅ 안전장치 포함: `or stop after 20 turns`
- ❌ 모호한 조건 금지: "the code is better", "database is optimized"

#### 상태 확인 / 취소 / 재개

```bash
/goal              # 상태 확인
/goal clear        # 취소 (stop / off / cancel 동일)
claude --resume    # 중단 세션 재개
```

#### 비대화형 자동화

```bash
claude -p "/goal CHANGELOG.md has entry for every PR merged this week"
```

### 4단계 — Agent View 로 여러 세션 관제

```bash
claude agents      # 열기 (Esc로 닫음)
```

#### 핵심 키

| 키 | 동작 |
|---|---|
| Enter / → | 세션 연결 |
| ← | 분리 (Agent View 복귀) |
| Space | 미리보기 |
| Alt+1~9 | N번째 세션 바로 연결 |
| Ctrl+R | 세션 이름 변경 |
| Ctrl+T | 세션 pin |
| Ctrl+X | 세션 중지 (2초 내 재클릭 시 삭제) |

#### 세션 필터링

- `s:blocked` — 🚨 **내 입력 기다리는 세션만** (실무 최다 사용)
- `a:<에이전트>` — 특정 에이전트 세션
- `#<PR번호>` — PR 관련 세션

#### 터미널 명령

```bash
claude --bg "리팩토링 진행해줘"
claude attach <session-id>
claude logs <session-id>
claude respawn <session-id>
claude respawn --all
```

### 조합 — 한 번에 굴리기

```
1. claude agents → Agent View
2. 여러 세션 디스패치
3. 각 세션에 /goal 설정
4. s:blocked 필터로 응답 필요 세션만 확인
```

여기에 1단계 기준을 더하면 흐름이 완성됩니다. 독립 작업이 5개 이상이고 찾기·판정·변환·수집 유형이면 한 세션에서 다이내믹 워크플로우로 넓게 퍼뜨리고, 서로 다른 큰 작업 여러 개는 세션을 나눠 각각 `/goal` 을 건 뒤 Agent View 에서 막힌 세션만 응답합니다.

## 활용 예시

- **콘텐츠 감사** (워크플로우·판정): 20개 이상의 캐러셀 디자인 시스템 일관성을 일괄 점검합니다.
- **시장 분석** (워크플로우·수집): 19개 해외 유튜브 채널 트렌드를 분석하고 한글화 후보 점수를 산정합니다.
- **데이터 검증** (워크플로우·찾기): 70개 이상의 가이드 문서 간 상충되는 내용을 일괄 탐지합니다.
- **광고주 매칭** (워크플로우·판정): 광고주 가이드라인과 자산을 1:1로 대조해 자동 리포트를 생성합니다.
- **테스트 복구** (`/goal`): `/goal all tests in test/auth pass and the lint step is clean` 을 걸어 두고 다른 일을 합니다.
- **주간 정리 자동화** (`/goal` + `claude -p`): 이번 주 머지된 PR마다 CHANGELOG 항목이 생길 때까지 비대화형으로 돌립니다.
- **동시 다발 작업 관제** (Agent View): `claude --bg` 로 리팩토링·문서화 세션을 띄워 두고 `s:blocked` 로 내 입력이 필요한 세션만 처리합니다.

## 💡 아이디어

- 자주 쓰는 병렬 점검(예: 문서 오탈자·규격 판정)을 한 번 잘 돌린 뒤 `/workflows` 에서 `s` 로 저장해 두면, 다음부터는 `/이름 항목1, 항목2` 한 줄로 재실행하는 팀 공용 도구가 됩니다.
- 여러 시장 분석 에이전트를 동시에 돌려 결과를 비교하거나, 여러 전문가 역할 에이전트가 하나의 기술 문제를 나눠 보는 시뮬레이션에도 응용할 수 있습니다. 다만 이런 작업은 1단계 기준상 '추론'에 가까우므로 결과의 정확성 검증 절차가 필수입니다.
- 워크플로우로 넓게 수집·판정한 결과를 받아, 후속 수정 작업은 한 세션에서 `/goal` 로 조건이 맞을 때까지 반복시키는 2단 구성이 효율적입니다.

## 주의사항

### 판단·품질

- **실수도 증폭된다**: 속도 향상만큼 오류도 함께 늘어납니다. 병렬 결과는 반드시 검증하세요.
- **지어낸 정보 경계**: 1인칭 문장이나 근거 없는 단정이 보이면 의심합니다. 여러 에이전트가 비슷한 내용을 썼다면 같은 '빈칸'을 각자 채운 것일 수 있습니다.
- **조직화된 무의미**: 에이전트가 에이전트를 검사하는 과정에서 '조직화된 무의미'를 대규모로 생산할 위험이 지적되고 있습니다. 결과물의 질적 관리가 중요합니다.
- **새 이름, 익숙한 패턴**: '그래프 엔지니어링'은 새로운 이름일 뿐, 앤트로픽의 'Building Effective Agents'(2024) 등에서 논의된 Orchestrator-workers, Parallelization 패턴과 유사합니다. 초기 아이디어는 2026년 6월에 언급되었고, 'graph engineering'이라는 용어는 2026년 7월에 커뮤니티에서 탄생했습니다.

### 다이내믹 워크플로우

- **버전·플랜**: Claude Code v2.1.154 이상. Max · Team 은 자동 ON, Pro · Enterprise 는 직접 켜야 합니다.
- **런타임 제한**: 동시 최대 16 에이전트, Run당 최대 1,000 에이전트까지 가능합니다.
- **비용**: 일반 세션보다 토큰 소모가 큽니다(위 실험에서 토큰 자릿수가 달라짐). 큰 작업 전 작은 단위로 테스트하고, 단계별로 모델을 다르게 라우팅하는 전략이 필요합니다.
- **권한 모드**: 'Default' 모드에서 'Yes, and don’t ask again'을 선택하면 해당 워크플로우는 승인 단계 없이 자동 실행됩니다. 'Auto' 모드, `ultracode` 가 켜져 있거나 `Bypass permissions / claude -p / Agent SDK` 사용 시에는 권한 확인 없이 자동 실행됩니다.

### `/goal` · Agent View

- Claude Code v2.1.139 이상 필수입니다.
- 세션당 목표는 1개만 걸 수 있습니다.
- 모호한 조건 = 무한 루프 위험 → 안전장치(턴 수 제한, 예: `or stop after 20 turns`)를 반드시 넣으세요.
- 평가자는 **출력만 봅니다** — 파일/시스템 상태를 자동으로 체크하지 않습니다. 조건은 테스트·린트·`git status` 처럼 실행 결과가 출력에 찍히는 형태로 쓰세요.
- `disableAllHooks` 설정 시 `/goal` 이 작동하지 않습니다.
- 동시 10+ 세션은 RAM 16GB+ 를 권장합니다.
