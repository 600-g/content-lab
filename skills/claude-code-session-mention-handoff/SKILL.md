# 클로드 세션 간 업무 인계하기

💡 이 스킬은 **Claude Code**에서 여러 터미널 세션을 열어두고 `@세션이름` 멘션으로 한 세션의 작업 내용을 다른 세션에 그대로 인계하는 스킬입니다. 이름 규칙(공백 금지, 중복 금지)만 지키면 복붙 없이 세션끼리 맥락을 주고받을 수 있습니다.

## 이게 뭔가요?

**Claude Code**에는 열려 있는 다른 세션에 `@세션이름`을 쳐서 메시지를 보내는 기능이 있습니다. 터미널을 여러 개 띄워놓고 작업하는 사람(메일함, 오가닉 콘텐츠, 협업 콘텐츠, 강의용 세션 등)이 세션 사이에 확인한 내용을 옮길 때 복붙·재설명 없이 바로 넘길 수 있게 해줍니다.

문제는 이 기능이 "부르는 이름"을 정확히 알아야만 작동한다는 것입니다. 터미널 탭에 적어놓은 이름과 클로드가 실제로 인식하는 이름(`agentName`)이 다를 수 있고, 이름에 공백이 있거나 다른 세션과 이름이 겹치면 메시지가 조용히 엉뚱한 곳으로 갑니다. 에러 메시지 없이 오배송되는 게 핵심 함정입니다.

💰 유료 필요: Claude Max (또는 사용량이 소모되는 Claude Code 요금제) — 세션을 여러 개 열어두고 오래된 대화를 이어받을수록 토큰 사용량이 커집니다.
✅ 무료 대안: 없음 — 이 기능은 Claude Code CLI 고유 기능이라 다른 도구로 대체할 수 없습니다.

지원 조건: **맥·리눅스**만 가능(윈도우 미지원), Bedrock·Claude Platform on AWS·Google Cloud Agent Platform·Foundry 환경 미지원, **버전 2.1.232 이상** 필요(`claude update`로 갱신).

## 따라하기

### 1. 세션을 열 때 이름을 붙인다

이름은 세션이 열릴 때 플래그로 붙입니다. 나중에 붙이면 안 되고, 지을 때 규칙을 지켜야 합니다.

```
claude -n mail
claude -n organic
claude -n 협업
claude -n 클래스101
```

이름 규칙은 두 가지뿐입니다: **공백을 넣지 않는다**, **짧게 짓는다**. 한글도 등록되고 호출도 되지만 `@` 자동완성 목록에 안 뜨고, 칠 때마다 한영 전환이 들어가서 불편합니다. 한글로 짓고 싶으면 `클래스101`처럼 붙여쓰거나 `클래스-101`처럼 하이픈을 넣으세요.

### 2. 진짜 이름(agentName)을 확인한다

터미널 탭에 적은 이름은 화면에만 있는 글자이고, 클로드는 그걸 읽지 않습니다. 이름을 안 주고 세션을 열면 `프로젝트폴더명-랜덤2글자` 형식의 이름이 자동으로 붙습니다. 세션 기록에는 이름을 담는 자리가 두 군데 있습니다.

| 필드 | 뭔가 | 누가 보나 |
|---|---|---|
| customTitle | 창에 뜨는 제목 | 사람이 봅니다 |
| agentName | 멘션 주소록에 올라가는 이름 | `@`가 씁니다 |

보통은 두 값이 같지만(`claude -n mail`로 열면 둘 다 `mail`), 어긋나는 경우가 있습니다. 실제 멘션 주소는 이 명령으로 확인합니다.

```
claude agents --json | python3 -c "import json,sys;[print(a.get('name')) for a in json.load(sys.stdin)]"
```

여기 뜨는 이름이 `agentName`이고, 창 제목과 다르면 그게 함정입니다. 세션에 이름을 안 붙이면 `@`는 사실상 못 씁니다 — 기능이 안 되는 게 아니라 부를 이름이 없는 겁니다.

### 3. 이름이 걸리지 않는 두 가지 원인을 구분한다

이름을 제대로 붙였는데도 `@`가 안 먹는 경우가 있습니다.

| 세션 이름 | @ 자동완성 목록에 | 다 쳤을 때 |
|---|---|---|
| mail (영문) | 뜹니다 | 걸립니다 |
| 협업 (한글, 공백 없음) | 안 뜹니다 | 걸립니다 |
| 클래스101 1강 커리큘럼 구성 기획 (공백 있음) | 안 뜹니다 | 안 걸립니다 |

한글 이름은 자동완성 목록에는 안 나오지만 `@협업`처럼 끝까지 치면 실제로 전송됩니다. 목록에 없어서 안 되는 줄 알기 쉬운데, 되는데 안 보이는 것뿐입니다.

반면 이름에 공백이 있으면 `@클래스101`까지만 이름으로 읽히고 뒤의 `1강 커리큘럼 구성 기획`은 그냥 문장으로 흘러갑니다. 그런 이름의 세션은 없으니 매칭에 실패하고, 실패했다는 알림 없이 엉뚱한 세션에 메시지가 도착합니다(받은 쪽은 파일 이름을 부른 걸로 알아듣기도 합니다). **세션 이름은 공백 없이 지으세요.**

### 4. 이름 충돌 시 규칙을 이해한다

멘션 주소는 컴퓨터 안에서 하나뿐이어야 합니다. 세션이 뜰 때 그 이름을 이미 쓰는 세션이 있는지 검사하고, 있으면 **새로 뜬 쪽이 이름을 양보**하고 자동 이름을 받습니다. 창 제목(`customTitle`)은 이 검사를 안 거쳐서 `-n` 값을 그대로 가져가기 때문에 두 값이 갈라집니다.

```
claude -r <세션ID> -n 협업
```

| 결과 | |
|---|---|
| 창 제목 (customTitle) | 협업 으로 바뀝니다 |
| 멘션 주소 (agentName) | 양보하고 자동 이름을 받습니다 |

`-r`이 문제가 되는 건 원본 세션을 끄지 않기 때문입니다. 같은 이름으로 이어 열면 자기 자신과 겹쳐서 매번 양보당하고, 끝난 옛 세션이 그 이름을 계속 붙들고 있어서 `@협업`으로 보내면 지금 작업 중인 창이 아니라 몇 시간 전에 멈춘 껍데기로 갑니다. 에러는 안 납니다. 이름을 재사용할 거면 옛 세션부터 정리해야 합니다.

```
claude stop <id>
```

애매하면 이름 대신 `claude agents` 목록에 뜨는 `[f655ff]` 같은 여섯 자리 ref로 부르는 게 확실합니다.

### 5. 켜둔 채로 이름을 바꾸려면 /rename

세션 안에서 슬래시 명령을 칩니다.

```
/rename 협업
```

(별칭 `/name`) 이라고 치면 `Session renamed to: 협업`이 뜨고, 창 제목뿐 아니라 멘션 주소까지 바뀝니다. 세션을 끄거나 다시 열 필요가 없습니다.

단, `/rename`은 중복을 막지 않습니다. 세션이 뜰 때는 이름이 겹치면 양보시키지만, `/rename`으로는 이미 남이 쓰는 이름을 그냥 가져갑니다. 그러면 같은 이름의 세션이 두 개가 되고 `@`가 어디로 갈지 알 수 없습니다. 순서를 지키세요 — **이름을 쥐고 있던 옛 세션을 먼저 닫고, 그다음에 `/rename`**.

### 6. -n, -r, --fork-session 세 가지를 구분한다

| 명령 | 무슨 일이 일어나나 | 이름은 |
|---|---|---|
| `claude -n class` | 빈 세션을 새로 만듭니다 | class 로 붙습니다 |
| `claude -r <세션ID> -n class` | 있던 대화를 다시 펼칩니다 | 창 제목만 class. 멘션 주소는 양보당합니다 |
| `claude -r <세션ID> --fork-session -n class` | 그 대화를 복사해 새 세션을 만듭니다 | class 로 붙습니다 |

`-n`은 이 창을 뭐라고 부를지를 정하고, `-r`은 어떤 대화를 이어갈지를 정합니다. 서로 상관없어서 같이 적어도 문법 오류는 안 나지만, 그 이름을 쓰는 세션이 살아 있으면 멘션 주소는 양보당합니다.

`--fork-session`은 개명 수단이 아니라 대화를 복사해서 새 세션으로 갈라낼 때 씁니다. 원본이 그대로 남아 세션이 하나 늘어나므로, 이름만 바꾸고 싶다면 `/rename`을 쓰세요. fork 후 원본이 필요 없으면 정리합니다.

```
claude agents --json
claude stop <원본id>
```

돌아가고 있는 백그라운드 세션은 `-r` 자체가 거부되며, `is currently running as a background agent`라는 안내와 함께 `--fork-session`을 쓰라고 알려줍니다.

### 7. 함께 쓰는 명령어

| 명령 | 하는 일 |
|---|---|
| `claude -n <이름>` | 이름 붙여서 세션 열기 — @ 의 전제 |
| `@<이름>` | 그 세션으로 메시지 보내기 |
| `claude agents` | 살아 있는 세션 목록 보기 (터미널을 붙잡아야 해서 스크립트에서는 안 됨) |
| `claude agents --json` | 같은 목록을 스크립트용으로 (TTY 없어도 됨) |
| `claude --bg "<할 일>"` | 백그라운드 에이전트로 띄우기 |
| `claude attach <id>` | 백그라운드 세션을 지금 터미널로 가져오기 |
| `claude logs <id>` | 그 세션이 뭘 했는지 보기 |
| `claude stop <id>` | 그 세션 정리하기 |
| `/rename <이름>` | 켜둔 세션의 이름 바꾸기 (세션 안에서 치는 슬래시 명령) |
| `claude -r <세션ID>` | 지난 대화 이어받기 |
| `claude -r <세션ID> --fork-session` | 이어받되 복사본으로 갈라내기 |

### 8. 세션 상태를 확인한다

창을 다 띄워놓지 않아도 어느 세션이 일하고 있는지 볼 수 있습니다.

```
claude agents --json | python3 -c "import json,sys;[print(a.get('name'),a.get('status','-')) for a in json.load(sys.stdin)]"
```

| 상태 | 뜻 | 기본 목록에 |
|---|---|---|
| blocked | 뭔가 기다리다 멈춤 (또는 프로세스가 이미 죽음) | 보입니다 |
| done | 할 일을 끝냄 | 안 보입니다 — claude agents --all 을 써야 뜹니다 |
| busy / idle | 지금 돌고 있음 / 입력 대기 중 | 보입니다 |

`busy`면 그 세션이 일하는 중이고 `idle`이면 입력을 기다리는 중입니다. `blocked`인데 `claude logs`로 안이 안 읽히고 프로세스 번호도 없으면, 표시만 남아 있고 실제 프로세스는 죽은 상태입니다. 대화 기록은 파일로 남아 있어서 `claude -r <세션ID>`로 되살릴 수 있습니다.

## 활용 예시

**메일함 → 협업 세션으로 인계**: `mail` 세션에서 메일 하나를 확인한 다음 `@협업 으로 이 내용 넘겨봐`라고 치면, 보낸 쪽 화면에는 `"○○○ 인계" → sent to 협업 — another Claude session on this machine`이 뜨고, 받은 쪽에는 `@ mail`로 시작하는 메시지가 도착합니다. 이때 예상과 다른 점 두 가지가 있었습니다.

1. 문장 한 줄이 아니라 정리된 인계장이 갔습니다. "이 내용 넘겨봐" 한 마디였는데, 보내는 세션이 핵심 항목을 표로 묶고, 원문을 다시 찾아갈 수 있게 식별자를 붙이고, 확인이 필요한 지점을 따로 뽑아 보냈습니다. 요약해서 넘기라고 시킨 적은 없었습니다.
2. 받은 세션이 자기가 아는 것과 대조해서 판단을 붙였습니다. 협업 세션은 그걸 받고 이번 달 남은 일정과 겹치는지 따져서 "언제쯤이 비어 있다"까지 답했습니다. 메일함 세션은 그 일정을 모릅니다 — 복붙과 다르게, 받는 세션이 자기 맥락 위에 얹어서 다시 읽는 방식입니다.

**주의: 아무 세션에나 넘기지 않기**: 릴스 작업을 시키던 세션에 다른 건을 넘겼더니 "이 세션은 원래 릴스 작업 중이었는데 이건 메일함 쪽이 맞아 보인다"며 되물었습니다. 받는 세션이 하던 일이 밀리기 때문에, 관련 없는 세션에 넘기면 원래 맥락이 흐려집니다.

**오래된 세션을 이어받을 때**: 5일 된 세션을 열면 이런 안내가 먼저 뜹니다.

```
This session is 5d 12h old and 401.5k tokens.
Resuming the full session will consume a substantial portion of your usage limits.
We recommend resuming from a summary.
1. Resume from summary (recommended)
2. Resume full session as-is
3. Don't ask me again
```

요약본으로 이어받으면 사용량을 크게 아끼면서도 작업 맥락은 그대로 이어집니다.

## 주의사항

걸릴 확률 순으로 정리한 15가지입니다.

- 세션에 이름이 없으면 `@`로 못 부릅니다
- 창 제목과 멘션 주소는 별개 필드라, 화면에 보이는 이름으로 못 부를 수 있습니다
- 멘션 주소는 컴퓨터 안에서 하나뿐이라, 겹치면 새로 뜬 쪽이 양보하고 자동 이름을 받습니다
- `-r`은 원본을 안 꺼서, 같은 이름으로 이어 열면 자기 자신과 겹쳐 매번 양보당합니다
- 그래서 `@`가 이름을 쥐고 있는 옛 세션(껍데기)으로 갑니다 — 에러는 안 납니다
- 켜둔 채 이름을 바꾸려면 `/rename <이름>`입니다 (멘션 주소까지 바뀝니다)
- `/rename`은 중복을 안 막습니다 — 같은 이름 두 개가 생기고, 그러면 어디로 갈지 모릅니다
- 한글 이름은 자동완성 목록에 안 뜹니다 (끝까지 치면 걸립니다)
- 이름에 공백이 있으면 못 부르고, 오류 없이 다른 세션으로 갑니다
- `--fork-session`은 개명 수단이 아니고, 원본이 남아 세션이 늘어납니다
- 돌아가고 있는 백그라운드 세션은 `-r`이 거부됩니다
- 오래된 세션을 열면 요약본으로 받을지 먼저 물어봅니다
- 이름 안 붙인 세션들이 자동완성을 어지럽힙니다
- `blocked`인데 프로세스는 죽은 유령 세션이 남고, `done`은 `--all` 없이는 안 보입니다
- 맥·리눅스만 되고 2.1.232 이상이어야 합니다 (Bedrock·Claude Platform on AWS·Google Cloud Agent Platform·Foundry 미지원)

정리하면: 새로 여는 창이면 `claude -n mail`, 이미 열려 있는 창이면 `/rename mail`. 둘 다 그 이름을 쓰는 세션이 없어야 온전히 먹습니다. 이름은 필요 없고 대화만 이어가고 싶으면 `claude -r <세션ID>`만 쓰면 됩니다.
