# 화면 AI와 생각 AI를 API로 연결

💡 이 스킬은 **페이블(화면)**과 **아스트라(생각)**를 **클로드 코드**가 짜주는 통로(API)로 이어 붙여서, 예쁘기만 하거나 똑똑하기만 한 반쪽짜리 AI 앱이 아니라 실제로 작동하는 AI 앱을 만드는 6단계·4개 프롬프트 세트입니다.

## 이게 뭔가요?

AI 도구를 혼자 쓰면 꼭 한쪽이 빕니다.

| 혼자 두면 | 그래서 생기는 일 |
|---|---|
| 페이블 5.1 | 화면은 잘 만드는데 생각을 못 합니다 → 예쁜데 아무 답도 안 나오는 껍데기 |
| 아스트라 | 생각은 잘하는데 화면이 없습니다 → 결국 채팅창에서만 씁니다 |

둘을 붙이면 쓰는 사람은 그냥 화면만 누르는데, 뒤에서는 진짜 AI가 생각해서 답을 내놓습니다. 식당으로 치면 홀(사람이 앉는 곳)과 주방(요리가 만들어지는 곳)입니다. 홀만 있으면 음식이 안 나오고, 주방만 있으면 손님이 앉을 데가 없습니다.

페이블과 아스트라는 자동으로 붙지 않습니다. 버튼 하나 눌러서 이어지는 기능이 없습니다. 둘 사이의 통로(API)를 직접 만들어야 하고, 그 통로를 대신 짜 주는 게 **클로드 코드**입니다.

| 이름 | 맡는 일 | 누가 만드나 |
|---|---|---|
| 페이블 | 화면 | 페이블이 만들어 줍니다 |
| 아스트라 | 생각 | 이미 있습니다 (프로젝트에서 실제로 쓸 수 있는 오픈AI 모델/통로) |
| 통로 | 둘을 잇는 것 | 없습니다. 내가 만듭니다 |
| 클로드 코드 | 그 통로를 짜 주는 사람 | — |

💰 유료 필요: 클로드 코드(Claude 구독), 아스트라 호출용 오픈AI API 키
✅ 무료 대안: 아스트라 자리에 다른 LLM API(Claude API, Gemini API 등)로 교체해도 구조는 동일합니다

### 헷갈리는 말 사전

| 여기서 쓴 말 | 원래 말 | 무슨 뜻 |
|---|---|---|
| 통로 | API | 프로그램끼리 주고받는 창구 |
| 창구 하나 | 엔드포인트 | 요청을 받는 주소 한 개 |
| 화면 | 프런트엔드 | 사람이 보고 누르는 쪽 |
| 통로 쪽 | 백엔드 / 서버 | 사람 눈에 안 보이는, 실제 일이 돌아가는 쪽 |
| 열쇠 | API 키 | 통로를 쓸 수 있게 해 주는 비밀 문자열 |
| 정해진 모양 | 구조화 출력 / JSON | 칸 이름이 미리 정해진 답의 틀 |
| 끊는 시간 | 타임아웃 | 너무 오래 걸리면 포기하는 시간 |
| 설정값 | 환경 변수 | 코드 밖에 따로 두는 값 (열쇠 등) |

## 따라하기

### 1. 아이디어를 정한다

한 문장이면 됩니다. 예: 「복잡한 시장 자료를 눌러 보는 금융 화면으로」
같이 적어 두면 편한 것: 누가 쓰나 / 사람이 무엇을 넣나 / AI가 무엇을 돌려줘야 하나. 아래 6-1 지시문의 대괄호에 그대로 들어갑니다.

### 2. 화면을 설계한다 — 페이블에 붙여넣기 (6-2)

기능은 하나도 없어도 됩니다. 만들 화면 여섯 개: 첫 화면 → 입력칸 → 보내기 → 기다리는 중 → 답 → 다시 묻기. 「기다리는 중」과 「오류」 화면을 빼먹기 쉬운데, AI는 답이 늦게 오거나 아예 안 올 때가 있어서 이 두 화면이 없으면 쓰는 사람은 고장 난 줄 압니다.

```
[만들 것] 의 페이블 화면을 같이 설계해 줘.
사람이 할 수 있어야 하는 것: [사람이 하는 일]
돌려받는 것 : [무엇을 받는지]
이 순서로 화면을 짜 줘.
첫 화면 → 입력 → 보내기 → 기다리는 중 → AI 답 → 눌러 보는 결과 → 다시 묻기
설계할 것: 페이지 구성 · 부품 · 입력칸 · 버튼 · 기다리는 화면 · 오류 화면
· 결과 카드 · 움직임 · 화면 전환 · 휴대폰에서의 모습
기준: 단순하게 · 고급스럽게 · 빠르게 · 한눈에 알아보게
없는 기능을 있는 척하지 않는다.
「보이기만 하는 것」과 「진짜로 이어지는 것」을 따로 표시하고,
통로가 만들어져서 돌려 보기 전까지는 전부 「아직 확인 안 됨」으로 둔다.
```

### 3. 뒤쪽(통로)을 만든다 — 클로드 코드 창에 붙여넣기 (6-1)

프로젝트 폴더를 열어 둔 채로 아래 지시문을 붙여 넣습니다. 사람이 넣은 말을 받는 창구 하나, 그 말을 아스트라에게 보내는 코드, 돌아온 답이 제대로 된 모양인지 검사하는 코드, AI 열쇠를 넣어 두는 자리(여기가 유일한 보관 장소)가 만들어집니다.

```
너는 내 선임 AI 제품 엔지니어다. 아래 조합으로 눌러 쓰는 AI 화면을 만들려고 한다.
화면 : 페이블 5.1
머리 : 아스트라 (이 프로젝트에서 실제로 쓸 수 있는 오픈AI 모델/통로를 쓴다)
개발 : 클로드 코드
만들 것 : [무엇을 만들지]
쓸 사람 : [누가 쓰는지]
사람이 넣는 것: [무엇을 입력하는지]
받고 싶은 답 : [아스트라가 무엇을 돌려줘야 하는지]
바깥 자료 : [붙일 자료가 있으면 / 없으면 「없음」]
원하는 화면 : [화면이 어떤 느낌이면 좋겠는지]
코드를 한 줄이라도 쓰기 전에 먼저 이것부터 한다.
1. 지금 작업 폴더를 들여다본다.
2. 이미 있는 파일이 무엇인지 확인한다.
3. 내가 준 자료·문서에서 페이블이 바깥과 이어지는 방법을 찾아낸다.
4. 실제로 쓸 수 있는 오픈AI 모델과 기능이 무엇인지 확인한다.
5. 연결 기능이 있다고 넘겨짚지 않는다.
6. 없는 통로 주소를 지어내지 않는다.
7. 없는 함수를 지어내지 않는다.
8. 없는 모델 이름이나 설정값을 지어내지 않는다.
9. 사람이 손으로 설정해야 하는 게 무엇인지 짚어 준다.
그다음 이 흐름대로 구조를 짠다.
사람 → 페이블 화면 → 사람이 넣은 말 → 통로 → 아스트라
→ 정해진 모양의 답 → 통로 → 페이블 화면 → 결과 보여 주기
내놓을 것: ㄱ. 사람이 쓰는 순서 ㄴ. 전체 구조 ㄷ. 필요한 파일
ㄹ. 필요한 서비스 ㅁ. 필요한 설정값 ㅂ. 요청이 오가는 순서
ㅅ. 답의 모양 ㅇ. 오류 처리 ㅈ. 안전에서 챙길 것
ㅊ. 시험 계획 ㅋ. 올리는 계획
답은 가능하면 칸이 정해진 모양으로 받는다. 예:
{ "요약": "", "핵심": [], "위험": [], "다음에 할 일": [] }
꼭 지킬 것
· 열쇠는 통로 쪽에만 둔다. 화면 코드에 비밀값을 절대 넣지 않는다.
· 사람이 넣은 말도, 모델이 준 답도 둘 다 검사한다.
· AI 쪽이 실패할 때를 반드시 처리한다. 기다리는 화면과 오류 화면을 만든다.
오래 걸리면 끊는 시간도 넣는다.
· 진짜로 돌려 보기 전에는 「된다」고 말하지 않는다.
· 페이블이 직접 못 하는 일이면, 가장 작은 다리를 어떻게 놓으면 되는지 설명한다.
· 문서나 열쇠가 없으면 멈추고, 내가 무엇을 줘야 하는지 정확히 말한다. 지어내서 만들지 않는다.
만드는 방식
한 번에 다 만들지 않는다. 먼저 구조 → 파일 → 연결 → 만드는 순서를 보여 주고
「1판 만들까요?」라고 물어본다.
내가 좋다고 하면, 돌아가는 가장 작은 판부터 만든다.
단계마다 돌려 보고 · 오류를 고치고 · 무엇이 되는지 말하고 · 확인 안 된 건 확인 안 됐다고 표시한다.
구현은 단순하게 간다.
```

맨 아래 「만드는 방식」이 중요합니다. 이걸 빼면 클로드 코드가 한 번에 다 만들어 버려서 어디가 잘못됐는지 못 찾습니다. 구조부터 보여 달라고 시키는 겁니다.

### 4. 답을 「정해진 모양」으로 받는다 (6-3, 6-4)

AI가 줄글로 답하면 화면에 꽂을 수가 없습니다. 「요약은 여기, 위험은 저기」 하고 자리에 넣으려면 칸 이름이 미리 정해져 있어야 합니다. 아래 지시문은 사람이 채팅창에 치는 게 아니라 **통로 코드 안에** 넣어 둡니다. `{{사람이 넣은 말}}`, `{{확인된 자료}}` 두 자리는 코드가 자동으로 채웁니다.

```
너는 어떤 화면 뒤에서 생각을 맡는 층이다.
쓰는 사람: [누가 쓰는지]
목적 : [무엇을 위한 것인지]
사람이 넣은 말: {{사람이 넣은 말}}
쓸 수 있는 자료: {{확인된 자료}}
받은 말을 살펴서 쓸모 있는 내용을 정해진 모양으로 돌려주는 게 네 일이다.
규칙
· 네게 주어진 내용만 쓴다.
· 살아 있는 자료를 지어내지 않는다.
· 출처를 지어내지 않는다.
· 사실과 네 해석을 구분해서 쓴다.
· 모르는 게 있으면 모른다고 말한다.
· 아래 모양에 맞는 답만 돌려준다.
돌려줄 모양
{
"요약": "한 문장",
"핵심": ["여러 개"],
"위험": ["여러 개"],
"다음에 할 일": ["여러 개"]
}
```

쓰고 계신 오픈AI 모델·버전이 모양을 지정해 받는 기능(구조화 출력)을 지원하는지 문서에서 확인하세요. 버전마다 다릅니다. 받은 뒤에는 모양이 맞는지 코드로 한 번 더 검사합니다. 검사에서 걸리면 오류 화면을 띄웁니다. 대충 지어낸 답을 화면에 올리면 안 됩니다.

### 5. 화면에 붙인다

여기가 제일 손이 갑니다. 페이블에서 바깥 창구를 부르는 방법은 쓰시는 판·설정마다 다릅니다. 페이블 문서에서 그 방법을 찾아 클로드 코드에 알려 주세요. 돌려받은 칸들을 화면 자리에 하나씩 꽂고, 진짜로 답이 돌아오는 걸 본 다음에 「됐다」고 하시면 됩니다.

### 6. 시험한다

한 번도 안 돌려 보고 끝내지 않습니다. 아래 8칸을 하나씩 켜 봅니다.

- 평범하게 넣었을 때
- 아무것도 안 넣고 눌렀을 때
- 이상한 걸 넣었을 때
- AI 쪽이 오류를 냈을 때
- 답이 아주 느릴 때
- 답 모양이 깨져서 왔을 때
- 있어야 할 칸이 비었을 때
- 휴대폰에서 봤을 때

## 활용 예시

- **금융 리서치 화면**: 「복잡한 시장 자료를 눌러 보는 금융 화면으로」를 만들 것에 넣고 → 6-1을 클로드 코드에, 6-2를 페이블에 각각 붙여넣으면 → 입력한 종목·기간을 아스트라가 분석해 요약/핵심/위험/다음 할 일 카드로 돌려주는 화면이 완성됩니다.
- **사내 문서 요약 도구**: 사람이 넣는 것에 「붙여넣은 회의록」, 받고 싶은 답에 「결정사항·액션아이템」을 넣으면 → 6-3의 `{{사람이 넣은 말}}` 자리에 회의록이 자동으로 채워져 정해진 모양(JSON)으로 요약이 돌아옵니다.
- **고객 문의 분류 화면**: 바깥 자료에 「없음」, 원하는 화면에 「빠르고 단순하게」를 지정하면 클로드 코드가 최소 기능 1판부터 만들고, 8칸 체크리스트로 빈 입력·오류·느린 응답까지 확인한 뒤 배포합니다.

## 주의사항

- **열쇠(API 키)는 화면 쪽에 절대 두지 않습니다.** 화면 코드는 누구나 열어 볼 수 있어서, 거기 열쇠를 두면 남이 내 요금으로 씁니다. 통로(백엔드) 쪽에만 둡니다.
- **사람이 넣은 말도, AI가 준 답도 둘 다 검사합니다.** 둘 다 이상할 수 있습니다.
- **돌려 보기 전에는 「된다」고 말하지 않습니다.** 화면만 그려 놓은 건 아직 아무것도 아닙니다.
- 6-1, 6-2, 6-3은 각각 다른 곳(클로드 코드 / 페이블 / 통로 코드 내부)에 들어갑니다. 헷갈리지 않도록 위 표를 다시 확인하세요.
- 클로드 코드가 「만드는 방식」 지시를 무시하고 한 번에 다 만들면, 구조 → 파일 → 연결 순서로 보여 달라고 다시 요청하세요.
