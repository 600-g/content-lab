# 큰 결정 AI 반박 검토

💡 AI에게 결정을 물으면 "좋은 결정이에요"가 돌아옵니다. 대신 **8가지 반대 렌즈**로 순차 반박시키거나 **5인 AI 위원회**가 논쟁·합의하게 해서, 아이디어를 죽이는 게 아니라 **방탄으로** 만듭니다.

## 이게 뭔가요?

이직, 사이드 프로젝트, 가격 인상, 협업 제안 수락, 큰 구매, 과금 모델 선택처럼 되돌리기 어려운 결정을 혼자 내리다가 나중에 후회한 경험이 있다면 쓸 만한 방법입니다. 단일 AI에 그냥 물으면 무의미한 긍정 답변이나 한쪽으로 치우친 답이 나오기 쉽습니다. 이 문서는 AI를 **반대 입장 조사관**으로 바꿔 약점·사각지대·반대 논리를 강제로 드러내는 두 가지 방식을 다룹니다.

- **8렌즈 적대적 검토 모드**: AI 하나가 사고 파트너가 되어 8가지 렌즈(Steel Man, 가정 해부, 사전 부검, 사각지대, 이해관계자 반대, 최악 타이밍, 더 간단한 대안, 틀렸을 때 프로토콜)를 순서대로 적용합니다. 2개 렌즈씩 분석 → 사용자 승인 → 다음 2개 진행 순으로, 한 번에 몰아 출력하지 않아 깊이를 유지합니다. 끝에 상위 리스크·비협상 체크·조기 경고 신호를 담은 완화 요약을 냅니다.
- **AI 위원회 (Council)**: Claude Code에서 쓰는 의사결정 지원 스킬입니다. 질문 하나를 던지면 서로 다른 관점의 AI 에이전트 5명이 독립 분석 → 피어 리뷰 → 트레이드오프 분석을 거치고, 의장 에이전트가 최종 결론을 냅니다. 단일 AI의 태생적 편향과 환각을 시스템적으로 차단하고, 필요하면 Gemini, GPT 등 경쟁 AI 모델을 호출해 '세컨드 오피니언(Second Opinion)'을 받을 수 있습니다. 위원회 멤버(에이전트 역할)는 비즈니스·프로젝트 성격에 맞게 재구성할 수 있습니다.

두 방식 모두 목표는 같습니다. 비판이 날카로울수록 최종 버전은 더 강해집니다.

### 어떤 방식을 언제 쓰나

| 구분 | 8렌즈 적대적 검토 모드 | AI 위원회 (Council) |
|---|---|---|
| 잘 맞는 결정 | 이미 마음이 기운 결정을 반박받고 싶을 때 (이직·구매·가격 인상·협업 수락) | 정답이 없는 모호한 문제, Go/No-Go, 방향성 피봇(Pivot), 선택지 A vs B |
| 관점 수 | AI 1명이 8개 렌즈를 차례로 | 에이전트 5명이 동시에 + 서로 교차 검토 |
| 결과물 | 렌즈별 관찰·심각도 + 완화 요약 (상위 3 리스크·비협상 체크·조기 경고) | 선택지별 트레이드오프 + 의장의 최종안·다음 스텝 |
| 진행 방식 | 대화형, 2개 렌즈마다 승인 | 한 번 질문하면 내부에서 논쟁·합의 후 결론 |
| 환경 | claude.ai Projects (무료 가능) 또는 Claude Code 스킬 | Claude Code CLI 환경 필요 |
| 난이도 | 초급 — 본문 복붙 | 고급 — 설치 + 에이전트 역할 커스터마이징 |

간단한 사실 확인 질문에는 둘 다 과합니다. 결정의 크기에 비례해 쓰세요. 큰 결정이라면 Council로 방향을 고른 뒤, 고른 안을 8렌즈 모드로 다시 반박받는 식으로 이어 써도 좋습니다.

## 따라하기

### 방법 1 — 8렌즈 적대적 검토 모드

#### 설치 A: Claude Project 사용자 (웹 버전)

1. claude.ai 접속 후 좌측 사이드바에서 **Projects** 클릭
2. **New Project** 버튼 클릭
3. 프로젝트 이름 작성 (예: `Devil's Advocate`)
4. 우측 **Set custom instructions** 클릭 후, 아래 [복사용 스킬팩 본문]을 통째로 붙여넣고 **Save**
5. 해당 프로젝트 안에서 결정 사항을 입력하면 끝 (결정 이력도 프로젝트 안에 누적됩니다)

💰 유료 필요: 없음 (Claude Free 플랜에서도 Projects custom instructions 사용 가능)
✅ 무료 대안: Gemini, ChatGPT 등 시스템 프롬프트/커스텀 지침을 지원하는 다른 AI 챗봇에도 동일한 본문을 붙여넣으면 동작합니다.

#### 설치 B: Claude Code 사용자 (터미널 환경)

에이전틱 AI인 클로드 코드의 글로벌 스킬로 설치해 두면 모든 로컬 환경에서 자동 호출됩니다.

1. 아래 [복사용 스킬팩 본문]을 복사합니다.
2. 터미널의 Claude Code에 본문과 함께 다음과 같이 입력합니다.

```
이 내용을 ~/.claude/skills/devils-advocate/SKILL.md 파일로 만들어줘.
```

3. 폴더 생성, frontmatter 작성, 본문 정리까지 클로드 코드가 알아서 처리합니다.
4. 사용법: 새 세션에서 큰 결정을 입력하면 자동 트리거됩니다. 명시적으로 부르고 싶다면 `"devils-advocate 스킬로 검토해 줘"` 라고 입력하세요.

#### 복사용 스킬팩 본문 (전체 원문)

```
🎭 시스템 정체성
당신은 적대적 검토 모드의 사고 파트너입니다. 사용자가 결정, 계획, 아이디어를 제안하면 다음 8가지 렌즈를 순서대로 적용해서 반박하세요. 사용자가 다른 지시를 하지 않으면 모든 렌즈를 시퀀스로 실행합니다. 목표는 아이디어를 죽이는 게 아니라 방탄으로 만드는 것입니다.
사용자가 다른 지시를 하지 않으면 모든 렌즈를 시퀀스로 실행하되, 반드시 한 번에 2개의 렌즈씩만 적용하여 분석 결과를 출력하세요. 2개의 렌즈 분석이 끝날 때마다 사용자에게 '다음 렌즈 분석을 계속 진행할까요?' 라고 묻고 승인을 받은 뒤 다음 렌즈로 넘어가야 합니다. 한 번에 8개를 전부 출력해서 분석의 깊이를 얕게 만들지 마세요.

🎬 세션 시작 멘트
"적대적 검토 모드 가동합니다. 이건 평가가 아니라 반대 입장 조사입니다. 비판이 날카로울수록 최종 버전은 더 강해져요." 그다음 결정/계획/아이디어를 한 문장으로 다시 확인한 뒤 진행. 모호하면 물어봅니다.

📐 8 렌즈 프레임워크
각 렌즈에서: 렌즈 이름 명시 → 2-4개의 날카로운 관찰 → 심각도 표시 (🔴 높음 / 🟡 중간 / 🟢 낮음)

🛡️ 렌즈 1 — Steel Man (반대 입장 최강 논리)
이 아이디어에 반대할 가장 강한 논리를 만드세요. 약한 반박이 아니라 진짜 똑똑하고 선의를 가진 비판자가 제기할 최선의 주장입니다.
- 형식: "가장 강한 반대 논리: [주장]. [맥락] 가진 사람이라면 [구체적 반박]이라 말할 것."

🔬 렌즈 2 — Assumption Autopsy (가정 해부)
이 아이디어에 깔린 모든 가정을 표면화하세요. 각 가정이 실제로 참인지 도전합니다.
- 카테고리: 시장/타깃, 자원, 행동, 재무, 경쟁
- 형식: 명시적으로 진술 → 확신도 평가 → 이 가정이 틀리면 무엇이 무너지나?

☠️ 렌즈 3 — Pre-Mortem (사전 부검)
6개월 뒤. 계획이 완전 실패했다. 실패 스토리를 작성하세요.
- 구조: 처음 잘못 가는 신호 → 어떻게 악화되었나 → 무엇을 놓쳤나 → 무엇을 무시했나

👁️ 렌즈 4 — Blind Spot Scan (사각지대 스캔)
근접성, 낙관 편향, 도메인 친숙도 때문에 못 보는 것들을 찾으세요. (가장 관련 깊은 2-3개만)
- 카테고리: 타이밍, 청중 미스매치, 기회비용, 2차 효과, 자존심/애착, 생존자 편향, 의존성 리스크, 평판 노출

⚔️ 렌즈 5 — Stakeholder Opposition Map (이해관계자 반대 지도)
이 결정을 반대, 지연, 방해할 이유가 있는 사람은 누구인지 찾으세요. (수동적 저항자, 외부 주체 포함)
- 형식: 이해관계자 / 예상 반대 / 위협 수준 (🔴🟡🟢) / 완화 전략

⏰ 렌즈 6 — Worst Timing Test (최악 타이밍 테스트)
외부 상황이 이 결정을 역효과로 만들 수 있는지 테스트하세요.
- 질문: 향후 30-90일 안에 방해할 일은? 다음 달에 큰 플레이어가 같은 걸 하면?

🪒 렌즈 7 — Simpler Alternative Test (더 간단한 대안 테스트)
50% 더 간단하게 만들고 80% 결과를 내는 버전이 있는지 찾으세요.
- 도전: 최소 실행 가능 버전은? 시간이 절반이라면 무엇을 잘라낼 건가?

🔄 렌즈 8 — What If We're Wrong Protocol (틀렸을 때 프로토콜)
가장 중요한 가정 또는 베팅 2-3개를 고르고 다음을 점검하세요.
- 가역성 체크 (되돌릴 수 있나?) / 조기 신호 체크 / 철수 기준 (언제 손절하나?)

📊 완화 요약 (8 렌즈 종료 후 출력)
[상위 3개 리스크 (심각도 × 확률 순위)]
- [리스크] — [왜 중요한가] — [완화 행동]
[진행 전 비협상 체크 사항]
- [진행 전에 사실이어야 하는 것]
[지켜볼 조기 경고 신호]
- [신호 1]: [구체적 관찰 지표]를 주시
[아직 답이 안 나온 가장 중요한 질문]
- [미해결 질문]

⚙️ 실행 규칙
1. 구체적으로: 일반 비판은 무용. 이름·숫자·시나리오 명시.
2. 잔혹하게 우선순위: 진짜 중요한 것만 표시.
3. 건설적으로: 모든 비판은 더 강한 버전을 가리켜야 함.
4. 비례 깊이: 사소한 결정은 가볍게, 큰 결정은 깊게.
5. 부드럽게 X: 외교적 모호함은 시간 낭비. 진짜 문제를 찾을 것.
```

#### 진행 흐름

1. 결정을 아래 「활용 예시」의 템플릿처럼 숫자·조건과 함께 입력합니다.
2. AI가 시작 멘트 후 결정을 한 문장으로 재확인합니다. 모호하면 질문이 돌아오니 답합니다.
3. 렌즈 1·2 → 승인 → 3·4 → 승인 → 5·6 → 승인 → 7·8 순으로 진행됩니다.
4. 마지막 완화 요약의 **비협상 체크 사항**과 **조기 경고 신호**를 실행 계획에 그대로 옮겨 둡니다.

### 방법 2 — AI 위원회 (Council)

#### 5인 5색 에이전트 보드

카운슬을 호출하면 아래 5명의 에이전트가 각자의 고유한 렌즈로 문제를 해부합니다.

| 에이전트 | 역할 | 특징 |
|---|---|---|
| **반대론자** | 잠재적 리스크 탐지 | "이게 왜 실패할까?", "어디서 문제가 터질까?"를 집요하게 파고들어 맹점을 찾아냅니다. |
| **원칙주의자** | 본질적 재설계 | 기존의 관습이나 뻔한 답변을 배제하고, 문제의 가장 기본적인 단위부터 처음부터 다시 설계합니다. |
| **확장론자** | 기회 창출 및 스케일업 | 현재 상황에서 놓치고 있는 추가적인 상승 여력(Upside)과 확장 가능성을 제시합니다. |
| **외부인** | 객관적 직관 | 업계의 복잡한 맥락이나 편견을 철저히 무시하고, 순수하게 문제 그 자체만 바라보고 해법을 던집니다. |
| **실행가** | 즉각적 액션 플랜 도출 | 복잡한 이론을 배제하고, '당장 오늘 할 수 있는 즉각적인 행동(Action Item)'만 명확하게 뽑아냅니다. |

#### 작동 프로세스

카운슬은 백그라운드에서 다중 시나리오를 동시에 평가해 가장 완성도 높은 답을 냅니다.

1. **독립 분석**: 5명의 에이전트가 각자의 관점으로 독립적인 답변 생성 (랜덤 셔플로 편향 방지)
2. **피어 리뷰 (Peer Review)**: 에이전트 간 상호 교차 검토로 허점을 보완하고 논리 보강
3. **트레이드오프 분석**: 선택지 간의 장단점(기회와 리스크)을 명확히 대조
4. **최종 결론**: 의장 에이전트가 모든 논의를 종합해 최종안 및 다음 스텝 정리

#### 설치와 사용

1. **설치**: 출처 페이지의 안내에 따라 Claude Code CLI 환경에 카운슬 스킬을 다운로드합니다.
2. **커스터마이징**: 사용할 에이전트의 역할(프롬프트)을 내 비즈니스에 맞게 고칩니다. 이 단계가 결과 품질을 가장 크게 좌우합니다. 예를 들어 반대론자는 그대로 두고, 확장론자를 "우리 업종의 재무 담당" 처럼 구체적인 역할로 바꾸는 식입니다.
3. **호출**: Claude Code 입력창에 `Ask the Council:` 트리거를 붙여 질문합니다. 선택지와 판단 기준(리스크·기회·근거)을 함께 적으면 트레이드오프 분석이 선명해집니다.

```
Ask the Council: 우리가 새로 출시하는 AI 교육 B2B 서비스의 과금 모델을 '월 구독'으로 할지, '건별 결제'로 할지 결정해야 해. 각 방식의 리스크와 기회를 다각도로 분석하고, 최종적으로 어떤 모델을 선택해야 할지 명확한 근거와 함께 제시해 줘.
```

#### 스킬 설치 전 맛보기 (일반 채팅창)

Claude Code 환경이 아직 없다면, 같은 구조를 대화창에 직접 지시해 흉내 낼 수 있습니다. 아래는 위 5인 보드와 작동 프로세스를 그대로 옮겨 구성한 예시 프롬프트입니다. 진짜 병렬 에이전트·다른 모델 호출은 일어나지 않으므로 효과는 스킬보다 약합니다.

```
아래 질문을 5명의 위원회로 검토해 줘.
위원: 반대론자(잠재적 리스크 탐지) / 원칙주의자(본질부터 재설계) / 확장론자(놓친 상승 여력) / 외부인(업계 맥락 무시한 객관적 직관) / 실행가(오늘 할 수 있는 행동만)
진행: 1) 각자 독립 분석 2) 서로의 답을 교차 검토해 허점 보완 3) 선택지별 기회와 리스크 대조 4) 의장이 최종안과 다음 스텝 정리
질문: [결정할 내용 + 선택지 + 조건]
```

### Council — 이럴 때 강력합니다

- 정답이 없는 모호한 문제: 신규 서비스 과금 모델(월 구독 vs 건별 결제), 타깃 고객층 선택
- 리스크가 큰 결정(Go/No-Go): 신규 사업 진출, 큰 투자 집행
- 방향성 피봇(Pivot)이 필요할 때: 지표가 정체된 프로젝트의 방향 재설정

## 💡 아이디어

- **2단 검토 파이프라인**: Council로 선택지 중 하나를 고른 뒤, 고른 안을 8렌즈 모드에 넣어 사전 부검과 철수 기준까지 받아 두면 "왜 이걸 골랐는가"와 "언제 접을 것인가"가 한 번에 정리됩니다.
- **결정 이력 아카이브**: 8렌즈 모드를 Claude Project로 운영하면 결정 이력이 프로젝트에 누적됩니다. 몇 달 뒤 완화 요약의 조기 경고 신호가 실제로 나타났는지 돌아보는 회고 자료로 씁니다.
- **AI 서비스 검증**: Council 구조를 AI 모델의 성능 개선·오류 검증에 활용하면 더 신뢰할 수 있는 AI 서비스를 만드는 데 도움이 됩니다.
- **전문 분야 의사결정**: 복잡한 법률, 금융, 의료 분야의 의사결정 과정에 적용해 여러 관점을 종합하고 잠재적 리스크를 미리 파악합니다. (최종 판단은 반드시 해당 분야 전문가가 합니다.)

## 주의사항

- **2개씩 진행이 핵심 설계**: 8렌즈 모드는 8개 렌즈를 한 번에 출력하지 않고 2개씩 나눠 진행해야 깊이가 유지됩니다. 결과가 한꺼번에 길게 나온다면 시스템 프롬프트가 제대로 적용되지 않은 것이므로 custom instructions/스킬 설치를 다시 확인하세요.
- **자동 트리거**: Claude Code 글로벌 스킬로 설치하면 큰 결정 관련 대화에서 자동으로 켜질 수 있습니다. 원치 않을 때는 다른 작업임을 명시하세요.
- **날카로움이 정상**: 비판이 날카로운 게 정상 동작입니다. 부드럽게 돌려 말하도록 유도하면 진짜 문제 발견이라는 목적이 무력화됩니다.
- **Council은 Claude Code CLI 필요**: 해당 환경에 익숙하지 않으면 진입 장벽이 있습니다. 먼저 8렌즈 모드나 위의 맛보기 프롬프트로 시작하세요.
- **역할 설계가 품질을 좌우**: Council 에이전트 역할을 커스터마이징할 때 명확하고 구체적인 프롬프트를 써야 결과의 질이 올라갑니다.
- **과잉 사용 금지**: 두 방식 모두 복잡한 사고 과정을 거치므로 간단한 사실 확인 질문에는 과합니다. 사소한 결정은 가볍게, 큰 결정은 깊게.
- **입력이 구체적일수록**: 숫자·기간·조건이 빠진 결정은 일반론적 비판만 돌아옵니다. 템플릿의 `[ ]` 를 최대한 구체적으로 채우세요.
