# AI 지침·메모리 파일 정리법

💡 모델은 계속 좋아지는데 옛 모델의 실수 때문에 쓴 지침은 남아 발목을 잡습니다. **CLAUDE.md는 지우고 반복되는 실패만 한 줄씩 되살리고**, **MEMORY.md는 200줄 안에** 인덱스로 유지합니다.

## 이게 뭔가요?

Claude Code가 매 세션 읽어 들이는 지침 파일은 두 종류입니다. 하나는 사용자가 직접 쓰는 **운영 매뉴얼**(`CLAUDE.md`), 다른 하나는 Claude가 작업하며 스스로 적는 **개인 노트**(`MEMORY.md`)입니다. 둘 다 컨텍스트 윈도우(작업대)를 차지하므로, 길고 낡을수록 공간을 낭비하고 최신 모델의 능력을 막는 불필요한 제약이 됩니다. 커스텀 스킬, 훅, 시스템 지침도 마찬가지입니다.

### 두 파일 비교

| 구분 | CLAUDE.md (운영 매뉴얼) | MEMORY.md (개인 노트) |
|---|---|---|
| 작성 주체 | 사용자 직접 | Claude가 자동 |
| 로드 시점 | 매 세션 **전체** 로드 | 매 세션 **첫 200줄만** |
| 주요 용도 | 아키텍처·컨벤션·핵심 규칙 | 학습된 패턴·명령어·선호도 |
| 팀 공유 | Git 체크인 가능 | Git 체크인 불가 |

`MEMORY.md` 를 셰프에 비유하면, 팀이 함께 보는 주방 운영 매뉴얼(`CLAUDE.md`)과 별개로 셰프가 주방에서 개인적으로 적어 두는 자동 메모 파일입니다.

- **저장 위치**: `~/.claude/projects/<프로젝트해시>/memory/` — 팀원과 공유하는 `CLAUDE.md` 와 달리 **사용자 개인 전용**입니다 (Git 공유 불가).
- **자동 기록**: AI가 작업하며 발견한 유용한 패턴을 스스로 파악해 백그라운드에서 저장합니다. "우리는 npm 대신 pnpm 쓴다고 기억해" 처럼 자연스럽게 지시하면 AI가 요약해 기록합니다.
- **200줄의 법칙 (가장 중요)**:

> 매 세션 시작 시 Claude는 `MEMORY.md`의 **첫 200줄까지만** 자동으로 읽어 들임.

작업대 공간 낭비를 막기 위한 장치이며, 200줄을 넘으면 토픽 파일로 분리해야 합니다.

### 정리 원칙 — Ablation(제거)

Claude Code 제작자인 Boris Cherny는 오래된 지침을 조금씩 다듬는 대신, 불필요한 지침을 주기적으로 삭제하고 꼭 필요한 것만 남기는 **'Ablation(제거)'** 방식을 제안합니다. 핵심은 세 줄입니다.

1. **일단 전부 지워봅니다**: 모든 지침을 제거한 상태에서 모델의 작동 방식을 관찰합니다.
2. **실제 작업을 해봅니다**: 평소 하던 코딩이나 작업을 그대로 수행하며, 지침 없이도 문제가 생기는지 확인합니다.
3. **같은 문제가 반복될 때만 다시 추가합니다**: 한 번의 실수로 지침을 추가하지 않고, 동일한 실수가 지속될 때만 꼭 필요한 지침 한 줄을 되돌립니다.

같은 원칙이 `MEMORY.md` 에도 적용됩니다. 쌓이는 대로 두지 않고, 오래된 항목은 지우고 비슷한 항목은 합쳐 200줄 안의 인덱스로 유지합니다.

💰 유료 필요: Claude Code 사용 가능한 플랜 (원문 기준 Claude Max)
✅ 무료 대안: 지침 파일 정리 원칙 자체는 Gemini, ChatGPT 등 커스텀 지침을 쓰는 다른 AI에도 그대로 적용됩니다. 단, `MEMORY.md` 자동 메모리는 Claude Code 전용입니다.

### 어떤 작업을 언제 하나

| 상황 | 할 일 |
|---|---|
| 새 모델이 나왔다 / 약 6개월이 지났다 / 지침이 길어져 답이 뻣뻣하다 | CLAUDE.md Ablation (방법 1) |
| `MEMORY.md` 가 150줄에 가까워졌다 | 오래된 항목 제거·통합·토픽 파일 분리 (방법 2) |
| 매달 한 번 | `wc -l` 로 줄 수 점검 + 자동 기록 내용 정확성·민감 정보 확인 |
| 같은 실수가 두세 번 반복된다 | CLAUDE.md 에 한 줄 추가 또는 "기억해" 로 MEMORY.md 에 기록 |

## 따라하기

### 방법 1 — CLAUDE.md 안전하게 덜어내기

과감한 전부 삭제가 부담스럽다면 다음 순서를 따르는 것이 안전합니다.

1. **백업**: 현재 `CLAUDE.md` 파일 등을 복사해 `CLAUDE.md.bak` 과 같이 백업합니다. 언제든 이전 상태로 돌아갈 수 있게 합니다.
2. **중복 정리**: 여러 파일(전역·프로젝트 CLAUDE.md, 스킬, 훅 등)에 걸쳐 중복되는 지침이 있는지 확인하고 정리합니다. `/doctor` 같은 도구를 활용할 수 있습니다.
3. **시스템 프롬프트 체감**: `CLAUDE_CODE_SIMPLE=1` 과 같이 시스템 프롬프트가 거의 없는 상태를 먼저 경험해 봅니다. 이를 통해 모델의 기본 성능을 파악합니다.
4. **평소처럼 일합니다**: 특별한 테스트 없이 1~2주간 평소 하던 작업을 수행하며 모델의 반응을 관찰합니다.
5. **반복되는 실패 기록**: 작업 중 반복적으로 발생하는 문제만 기록합니다. 한 번의 실수는 넘어가고, 비슷한 문제가 계속 나올 때만 지침을 추가합니다.
6. **짧게 다시 작성**: 추가하는 지침은 한 문제에 한 줄 정도로 간결하고 명확하게 씁니다.

지침을 다시 쓸 때의 기준은 아래와 같습니다.

- **예전 지침**: `❌ 코드를 작성할 때는 항상 타입을 명시하고 주석을 충분히 작성하고 테스트를 추가하며 기존 구조를 유지하면서…` (길고 모호함)
- **정리 후 지침**: `✅ 이 저장소는 pnpm을 쓴다. npm으로 실행하지 말 것.` (명확한 이유와 반복되는 실수 기반)

### 방법 2 — MEMORY.md 를 200줄 안에 유지하기

#### STEP 1. 위치 확인

```bash
ls ~/.claude/projects/
cat ~/.claude/projects/<프로젝트해시>/memory/MEMORY.md
```

#### STEP 2. 자연스럽게 학습시키기

```
"우리는 npm 대신 pnpm 쓴다고 기억해"
"이 프로젝트는 항상 TypeScript strict 모드야"
"테스트는 vitest 로 돌리고 jest 는 안 써"
"PR 브랜치는 feature/<title> 형식으로"
/memory  # 명시적 기록
```

#### STEP 3. 효과적인 메모리 5가지 패턴

1. **"왜"를 함께 기록** — "X를 쓴다" 보다 "X를 쓴다 (이유: Y 때문)"
2. **부정형 명시** — "Z는 절대 쓰지 마라" 금지 사항도
3. **반복 명령어 단축형** — "테스트는 `pnpm test --filter=core`로"
4. **사용자 선호 톤** — "에러 메시지는 한글로", "코드 주석 최소화"
5. **프로젝트 변천사** — "이전엔 X 썼다가 Y로 마이그레이션 완료"

이 패턴은 방법 1에서 CLAUDE.md 에 한 줄을 되살릴 때도 똑같이 통합니다. 특히 1번(이유)과 2번(금지)을 한 줄에 담으면 가장 짧고 강한 지침이 됩니다.

#### STEP 4. 200줄 초과 시 토픽 파일 분리

| 토픽 | 파일명 | 내용 |
|---|---|---|
| 디버깅 | `debugging.md` | 자주 만나는 에러 + 해결법 |
| 테스트 | `testing.md` | 전략, mock 패턴 |
| 빌드/CI | `deployment.md` | 배포 명령, CI 설정 |
| DB | `database.md` | 마이그레이션, 쿼리 패턴 |
| API 통합 | `apis.md` | 외부 API 호출 패턴 |

분리 후 `MEMORY.md` 는 **인덱스 + 가장 자주 쓰는 패턴**만 남깁니다.

#### STEP 5. 월 1회 점검

```bash
wc -l ~/.claude/projects/<프로젝트해시>/memory/MEMORY.md
# 200줄 가까우면:
# 1) 오래된 항목 제거
# 2) 토픽 파일로 분리
# 3) 비슷한 항목 통합
```

점검할 때 내용도 함께 봅니다. 자동 기록이 틀렸거나, 모델이 이제는 알아서 잘하는 일이라 필요 없어진 항목은 방법 1의 원칙대로 지웁니다.

### 점검 체크리스트

- [ ] `CLAUDE.md` 백업(`CLAUDE.md.bak`)을 만들었다
- [ ] 여러 지침 파일 사이의 중복을 정리했다
- [ ] 남은 지침이 전부 "반복된 실패" 또는 "모델과 무관한 필수 규칙"에서 나왔다
- [ ] 지침은 한 문제에 한 줄, 이유 또는 금지가 명확하다
- [ ] `MEMORY.md` 가 150줄 이하이고, 넘친 내용은 토픽 파일로 분리했다
- [ ] 자동 기록 내용 중 틀린 것·민감 정보가 없다
- [ ] `.claude` 폴더를 백업했다

## 활용 예시

- **새 모델 출시 직후**: 개인 프로젝트의 `CLAUDE.md` 를 백업하고 비운 뒤 1~2주 평소대로 작업합니다. npm으로 실행하는 실수가 반복될 때만 `이 저장소는 pnpm을 쓴다. npm으로 실행하지 말 것.` 한 줄을 되살립니다.
- **장황한 코딩 규칙 정리**: "타입을 명시하고 주석을 충분히…" 같은 긴 일반론을 지우고, 실제로 반복된 문제 하나당 한 줄로 바꿉니다.
- **메모리 비대화 해결**: `wc -l` 결과가 180줄이면 디버깅·테스트 관련 항목을 `debugging.md`, `testing.md` 로 옮기고 `MEMORY.md` 에는 인덱스만 남깁니다.
- **팀 규칙과 개인 선호 분리**: 팀이 합의한 컨벤션은 `CLAUDE.md` 에 두고 Git에 체크인하고, "에러 메시지는 한글로" 같은 개인 선호는 "기억해" 로 `MEMORY.md` 에 맡깁니다.

## 💡 아이디어

- AI 모델의 발전 속도에 맞춰 주기적으로(약 6개월마다 또는 새 모델 출시 시) 지침 파일을 재평가하는 프로세스를 자동화할 수 있습니다. 예를 들어 월 1회 `wc -l` 점검 결과와 지침 파일 목록을 알림으로 받아 정리 시점을 놓치지 않게 합니다.
- 되살린 지침마다 "언제, 어떤 실패가 몇 번 반복돼서 추가했는지"를 짧게 남겨 두면, 다음 Ablation 때 지워도 되는 지침을 빠르게 고를 수 있습니다.

## 주의사항

- **무조건 다 지우라는 뜻은 아닙니다**: 팀 합의 개발 규칙, 보안 정책, 컴플라이언스 요구사항, 절대 바뀌면 안 되는 프로젝트 제약, 배포/인프라 관련 필수 규칙, 특정 저장소의 명확한 컨벤션 등은 모델 능력과 별개로 유지해야 합니다.
- **팀 공유 파일은 혼자 지우지 않습니다**: 팀이 함께 쓰는 `CLAUDE.md` 는 혼자 판단해 통째로 삭제하면 안 됩니다. 개인 환경이나 실험 가능한 프로젝트에서 먼저 적용하세요.
- **과장된 사례 주의**: "프롬프트 80% 삭제"나 "대규모 리라이트" 같은 사례는 AI의 발전 정도를 보여주지만 그대로 일반화하기는 어렵습니다. AI에게 맡길 수 있는 작업 단위가 커졌다는 정도로 이해하세요.
- **속도보다 능력 활용**: 지침을 지운다고 무조건 빨라지는 것은 아닙니다. 불필요한 제약이 줄어 모델이 가진 능력을 더 그대로 쓸 수 있는지에 초점을 맞추세요.
- **200줄 법칙은 절대 무시하지 않습니다**: 201번째 줄부터는 세션에 실리지 않습니다. 150줄에 도달하면 정리하세요.
- **MEMORY.md 는 Git 체크인 X (자동 gitignore)**: 비밀번호·내부 정보가 들어 있을 수 있습니다. 민감 정보가 자동 저장될 수 있으니 정기 검토가 필수입니다.
- **자동 기록은 100% 정확하지 않습니다**: 월 1회 직접 점검하세요.
- **Claude Code 전용**: `MEMORY.md` 자동 메모리는 Codex/Cursor/Copilot 에는 적용되지 않습니다.
- **`.claude` 폴더 백업 권장**: 시스템 재설치 시 메모리가 손실됩니다.
